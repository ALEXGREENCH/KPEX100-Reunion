# Prism Vault

В библиотеке Reunion откройте «Примеры» и выберите **Prism Vault · Game Gear на GNEX**. Стрелки двигают персонажа. Кнопка 1 Game Gear соответствует A или Select на K-PEX и переключает фазу ворот. Соберите два осколка и доберитесь до выхода. Start или Play начинает новую попытку.

[Картридж](prism-vault.gg) содержит оригинальную программу Z80, комнату и графику. [Mobile C](prism-vault.mc) загружает эти же 32 КиБ из `VAULT.GGR` через GNEX VFS. Код картриджа опрашивает кнопки через порты `$DC` и `$00`, записывает узоры, карту и 12-битную палитру через порты VDP и сам проверяет столкновения, осколки и выход. На LCD K-PEX видна центральная область 160 × 144 без растягивания. [Руководство Sega для Game Gear](https://www.smspower.org/Development/GGOfficialDocs)

Интерпретатор рассчитан на фиксированный 32-КиБ картридж, часть инструкций Z80 и неподвижный фон Mode 4. Таймер приближённо отмечает VBlank каждые 20 мс. Рисуются только изменённые ячейки, одноцветный тайл выводится за одну операцию. Спрайты, переключаемые банки, прерывания, прокрутка, PSG и потактовая синхронизация требуют реализации.

При запуске сцена рисуется порциями в буфер. Первый игровой кадр появляется после отрисовки всей очереди, поэтому прошивке достаточно одного полного обновления LCD вместо 36 промежуточных. Кадр после загрузки и кадры управления сохранились побайтно.

При выключенном дисплее интерпретатор объединяет полные итерации двух распознанных циклов записи в VDP. Он сверяет команды в ROM и учитывает каждую гостевую инструкцию в прежнем бюджете таймера. Это ускоряет загрузку узоров и карты. В проверке полной Kingston 2.12 первый игровой кадр и кадр после движения совпали с предыдущей сборкой.

## Сборка

Для SGS на Windows положите оригинальные `mcc_GNEX.exe` и `MASM_GNEX.exe` из SDK 2.12 в одну папку. Общий [сборщик](../sgs_build.py) проверяет SHA‑256 и меняет дату окончания работы компилятора во временной копии. [Архив GNEX SDK 2.12](https://archive.org/details/gnex_sdk_v2.12)

```powershell
python demos/gg/build.py --rom-only --output prism-vault.gg
python demos/gg/build.py --sdk C:/path/to/sdk --output prism-vault.sgs
```

Для испытаний физической прошивки положите `prism-vault.sgs` в папку `GAME` и скопируйте туда же `prism-vault.gg` под именем `VAULT.GGR`. Контейнер использует XOR-A5 загрузчика Kingston. В Reunion файл уже вложен в [SGS](../../web/data/games/demo-prism-vault.sgs). Параметр `--cart test.gg` заменяет вложение для тестирования поддерживаемого набора команд.

[Интеграционный тест](../../tests/gg-demo.test.mjs) проходит оба фазовых барьера, оба осколка, выход и перезапуск, проверяет восстановление кадров без следов старой позиции и ошибку при неверном заголовке. Самостоятельный `.gg` отдельно прошёл тот же маршрут в [Gearsystem](https://github.com/drhelius/Gearsystem) версии 3.9.24-12-g1be9a12.

## Signal Breaker

Ведите платформу влево и вправо и разбейте восемь узлов отражённым шаром. На старте три попытки. Кнопка 1 Game Gear или A на K-PEX подаёт шар. Start или Play начинает заново.

[Исходник картриджа](signal_breaker.py) задаёт графику, столкновения, счёт, проигрыш и победу. Он собирает самостоятельный [ROM Game Gear](signal-breaker.gg), который исполняется тем же GNEX-интерпретатором, что и Prism Vault. Маршрут до победы и перезапуск проверены в [Gearsystem](https://github.com/drhelius/Gearsystem) и [тесте Reunion](../../tests/gg-signal-breaker.test.mjs).

```powershell
python demos/gg/build.py --signal-breaker --rom-only --output signal-breaker.gg
python demos/gg/build.py --signal-breaker --sdk C:/path/to/sdk --output BREAKER.SGS
```

Для Kingston 2.12 положите [BREAKER.SGS](../../web/data/games/demo-signal-breaker.sgs) и ROM под именем `BREAKER.GGR` в папку `GAME`. В прямом режиме Reunion читает этот же ROM из хвоста SGS.

При проверке оригинальная прошивка Kingston 2.12 прочитала картридж с виртуального диска, отобразила поле, подала шар, убрала первый узел и отработала нажатия в обе стороны. Signal Breaker учитывает события нажатия и отпускания клавиш, чтобы при смене направления не сохранялось предыдущее нажатие.

## Pulse Relay

Выберите одну из трёх дорожек кнопками влево и вправо, затем нажмите 1 на Game Gear или A на K-PEX. Когда цветная нота дойдёт до горизонтальной черты, нажмите стрелку под ней. На каждой дорожке 24 ноты и три скорости. Ошибка снимает одно из четырёх делений и обнуляет серию. После результата кнопка 1 повторяет дорожку, Start возвращает к выбору.

[Исходник Pulse Relay](pulse_relay.py) собирает [самостоятельный картридж](pulse-relay.gg) с игровым циклом на Z80. Темп зависит от VBlank Game Gear, а в GNEX от таймера обёртки. Звуковые подсказки отсутствуют. [Тест Reunion](../../tests/gg-pulse-relay.test.mjs) проверяет смену дорожки и темпа, ранние и неверные нажатия, удержание одной кнопки, победу, проигрыш и повтор. В [Gearsystem](https://github.com/drhelius/Gearsystem) картридж отдельно прошёл третью дорожку с результатом 24/24.

```powershell
python demos/gg/build.py --pulse-relay --rom-only --output pulse-relay.gg
python demos/gg/build.py --pulse-relay --sdk C:/path/to/sdk --output PULSE.SGS
```

Для Kingston 2.12 скопируйте [PULSE.SGS](../../web/data/games/demo-pulse-relay.sgs) и картридж под именем `PULSE.GGR` в папку `GAME`. В прямом режиме Reunion читает этот же ROM из SGS.

На оригинальной прошивке Kingston 2.12 с виртуальным диском проверены загрузка картриджа, выбор второй дорожки, запуск кнопкой A и попадание по первой ноте. Счёт и серия выросли до `01` на LCD.

## Freight Shift

Расставьте грузы на отмеченные клетки в четырёх комнатах. Стрелки двигают грузчика. За раз можно толкнуть один ящик. Кнопка 1 на Game Gear или A на K-PEX отменяет до 32 ходов, включая толчки. Start перезапускает текущую комнату или открывает следующую после решения.

[Исходник Freight Shift](freight_shift.py) содержит карты комнат, графику и игровой цикл Z80. [Самостоятельный картридж](freight-shift.gg) прошёл все четыре комнаты в [Gearsystem](https://github.com/drhelius/Gearsystem). [Тест Reunion](../../tests/gg-freight-shift.test.mjs) также проверяет недопустимый толчок двух ящиков, отмену толчка и последнего хода после победы, сброс и переполнение истории ходов.

```powershell
python demos/gg/build.py --freight-shift --rom-only --output freight-shift.gg
python demos/gg/build.py --freight-shift --sdk C:/path/to/sdk --output FREIGHT.SGS
```

Для Kingston 2.12 скопируйте [FREIGHT.SGS](../../web/data/games/demo-freight-shift.sgs) и картридж под именем `FREIGHT.GGR` в папку `GAME`. В прямом режиме Reunion читает этот же ROM из SGS.

На оригинальной Kingston 2.12 с виртуальным диском проверены толчок, отмена с побайтным восстановлением кадра, решение первой комнаты и переход во вторую кнопкой Play.

## Coil Runner

Перепрыгивайте провалы и патрули в трёх секторах. Стрелки влево и вправо задают направление, кнопка 1 на Game Gear или A на K-PEX поднимает героя в прыжок. В воздухе герой продолжает движение в выбранном направлении. Пружина позволяет добраться до верхнего настила. Две батареи открывают шлюз, а отмеченная флажком контрольная точка сохраняет собранный заряд после падения. Start перезапускает сектор или переводит в следующий после открытия шлюза и выхода.

[Исходник Coil Runner](coil_runner.py) содержит карты, графику, физику прыжков и патруль на Z80. Все три сектора [самостоятельного картриджа](coil-runner.gg) пройдены в [Gearsystem](https://github.com/drhelius/Gearsystem). [Тест Reunion](../../tests/gg-coil-runner.test.mjs) проверяет тот же игровой цикл, в том числе прыжок с пружины, возврат к флажку с сохранением заряда и финальный переход. На оригинальной Kingston 2.12 с виртуальным диском проверены загрузка ROM, батарея, прыжок через провал и возврат к контрольной точке.

```powershell
python demos/gg/build.py --coil-runner --rom-only --output coil-runner.gg
python demos/gg/build.py --coil-runner --sdk C:/path/to/sdk --output COIL.SGS
```

Для Kingston 2.12 скопируйте [COIL.SGS](../../web/data/games/demo-coil-runner.sgs) и картридж под именем `COIL.GGR` в папку `GAME`. В прямом режиме Reunion читает тот же ROM из SGS.
