# GNEX Bench

Оригинальный SGS для замеров на K-PEX 100 и других устройствах с загрузчиком GNEX v4. Тест начинается автоматически. После результатов нажмите OK / SELECT для повторного прогона. Нужна рабочая область LCD не менее 120 × 120. Результаты остаются на экране, файлы и сохранения приложение не меняет.

| Поле   | Что выполнено                                                                                                                                        |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| IDLE   | 24 одноразовых таймера по 20 мс без нагрузки. Это базовое время планирования событий.                                                                |
| CPU    | 24 таких же таймера и 8192 итераций целочисленной арифметики на событие. Итоговый контрольный код — `F57A`.                                          |
| LCD    | 24 таких же таймера, по 384 заливки 16 × 8 с установкой цвета и один `Flush` на событие. Прямоугольники перерисовывают одну и ту же область 96 × 48. |
| ITER/s | 196 608 итерации, делённые на полное время CPU в секундах.                                                                                           |
| RECT/s | 9216 вызовов заливки, делённых на полное время LCD в секундах.                                                                                       |

Фазы измеряются через `ResetTick(0)` / `GetTick(0)`. Это счётчик прошедшего времени в миллисекундах. Время включает ожидание таймеров и нагрузку самих событий. Разности `CPU − IDLE` и `LCD − IDLE` дают ориентир по дополнительному времени. Малая разность может быть следствием округления и разброса таймеров. Результат характеризует VM и цепочку вызовов GNEX, а частота CPU и скорость физического обновления LCD измеряются отдельно. [Sinjisoft Mobile C API, стр. 312–313](../../doc/reference-index.md#mobile-c--gnex)

## Как записать результаты

1. На K-PEX 100 с Kingston 2.12 скопируйте SGS в папку GAME и запустите из меню GAME. В Reunion выберите «GNEX Bench» в разделе «Примеры».
2. Дождитесь экрана результата и проверьте `CHECK F57A`. Повторите ещё два раза. Для браузерных замеров держите вкладку активной и запишите версию браузера и режим запуска.
3. Сохраните фотографию или снимок каждого результата. Для сравнения запишите точную модель, версию прошивки и GNEX, если она известна, а также хеш SGS. Сравнивайте медианы трёх значений IDLE, CPU и LCD отдельно.

| Модель и прошивка | GNEX / версия Reunion и режим | SHA-256 SGS | IDLE (мс) | CPU (мс) | LCD (мс) | CHECK |
| ----------------- | ----------------------------- | ----------- | --------- | -------- | -------- | ----- |
|                   |                               |             |           |          |          |       |

Прямой режим K-PEX в Reunion считает `GetTick` по монотонным часам хоста с шагом 20 мс. Режим совместимости телефона добавляет виртуальное время ARM. Для замера прямого режима используйте запись из библиотеки с явно заданным профилем K-PEX. В полной эмуляции прошивки гостевое время дополнительно зависит от модели ARM и таймеров. В контрольном прогоне полной Kingston 2.12 все три фазы дали 480 мс. В этом случае темп таймеров скрыл разницу между нагрузками. Для калибровки нужны отдельные замеры физического устройства.

## Сборка

Положите оригинальные `mcc_GNEX.exe` и `MASM_GNEX.exe` из [Sinjisoft GNEX SDK 2.12](https://archive.org/details/gnex_sdk_v2.12) в одну папку. Скрипт сверяет SHA‑256 и меняет год окончания работы только во временной копии компилятора.

```powershell
python demos/benchmark/build.py --sdk C:/path/to/sdk --output gnex-bench.sgs
```

Готовая сборка использует XOR `0xA5`: в проверке полной Kingston 2.12 оригинальный загрузчик прочитал и запустил эту форму из FAT. Для другого загрузчика, ожидающего обычный SGS SDK, передайте `--plain`.
