# Orbital Courier

В библиотеке Reunion откройте «Примеры» и выберите **Orbital Courier · NES на GNEX**. Стрелками проведите корабль через два пояса обломков и свяжите три маяка слева направо. Кнопка A или Select начинает новую попытку.

В SGS вложен оригинальный картридж `cart.nes` с кодом, картой и графикой. [Mobile C](orbital-courier.mc) читает файл через GNEX VFS, запускает инструкции RP2A03 с вектора сброса, подаёт ввод через строб и сдвиговый регистр `$4016` и выводит данные CHR-ROM, таблиц фона, палитр и первого спрайта. Сам картридж обрабатывает столкновения, порядок маяков и победу. На экране K-PEX видна центральная область 208 × 160 без масштабирования. [Схема NROM](https://www.nesdev.org/wiki/NROM) · [PPU](https://www.nesdev.org/wiki/PPU_programmer_reference) · [Контроллер NES](https://www.nesdev.org/wiki/NES_controller)

Интерпретатор рассчитан на этот прототип. Заголовок поддерживает iNES mapper 0 с одним или двумя банками PRG-ROM, одним банком CHR-ROM, горизонтальным или вертикальным зеркалированием. Реализована часть инструкций RP2A03. PPU обрабатывает один спрайт 8 × 8 и неподвижный фон. Таймер имитирует VBlank раз в 20 мс и постепенно рисует изменившиеся тайлы. Для более широкой совместимости нужны полный набор инструкций, IRQ/NMI, APU, прокрутка и потактовая модель PPU.

## Сборка

Для сборки SGS под Windows положите оригинальные `mcc_GNEX.exe` и `MASM_GNEX.exe` из SDK 2.12 в одну папку. Общий [сборщик](../sgs_build.py) проверяет SHA‑256 и меняет дату окончания работы компилятора во временной копии. Исходник картриджа находится в [build.py](build.py). [Архив GNEX SDK 2.12](https://archive.org/details/gnex_sdk_v2.12)

```powershell
python demos/nes/build.py --sdk C:/path/to/sdk --output orbital-courier.sgs
python demos/nes/build.py --rom-only --output orbital-courier.nes
```

Параметр `--cart test.nes` заменяет вложенный картридж для экспериментов с поддерживаемыми инструкциями и регистрами. Готовый [SGS](../../web/data/games/demo-orbital-courier.sgs) проверяется в прямом режиме Reunion [интеграционным тестом](../../tests/nes-demo.test.mjs) с полным прохождением и повторным запуском. Самостоятельный `.nes` отдельно прошёл тот же маршрут со столкновением и перезапуском в [JSNES 2.1.0](https://github.com/bfirsh/jsnes/tree/v2.1.0).
