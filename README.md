# K-PEX 100 — Reunion

Эмулятор Kingston K-PEX 100 и среды Sinjisoft GNEX для браузера и Windows.
Проект исполняет оригинальный ARM-код прошивки, интерпретатора GNEX и
графической библиотеки. Игровая логика и ресурсы поступают из исходных SGS.

[English quick start](README.en.md) · [Совместимость](doc/compatibility.md) ·
[Документация](doc/README.md) · [Играть в браузере](https://alexgreench.github.io/KPEX100-Reunion/)

Коллекция включает 9 прошивок, 102 SGS-приложения, 18 игр Anycall ADS, 3 быстрых состояния
и оригинальный модуль Swerve 2.1. Каталог фиксирует размеры, SHA-256 и
проверенные профили. Дополнительные файлы можно загрузить в браузере.

Во вкладке «Игры» доступны сборки SGS и ADS, восстановление
[Fortress Tournament](doc/fortress-tournament.md) и утилита Mosquito.
Во вкладке «Примеры» — четыре учебных SGS. Оригинальные вложения,
исходники и исследовательские находки доступны на
[странице архивов](https://alexgreench.github.io/KPEX100-Reunion/research/).
Для каждого архива сохранены источник, размер и SHA-256; найденные native PXO
и Flash не объявлены поддерживаемыми играми GNEX.

[World League и Bounce из S60](doc/s60-library-completion.md): полная World League 2005, её демо и Bounce! Rubberball Story теперь доступны из библиотеки. Это ранее сохранённые SGS с новыми парными проверками; ограничения меню и внешнего звука описаны отдельно.

[Aiolos из прошивок Oracom](doc/gnex-devices.md#oracom-игра-в-официальных-обновлениях) доступна в двух оригинальных сборках. Проверен первый уровень.

[Ladder из LG SD1250](doc/lg-legacy-compressed.md) запускается из библиотеки. В том же отчёте описана распаковка ранних SGS GVM.

[Игры Samsung Anycall ADS](doc/samsung-anycall-ads-mbin.md#запуск-в-браузере) доступны в веб-библиотеке из оригинальных MBIN со звуком SMAF. Для каждой проверены вход в игровой процесс и действие кнопки. Палитра, таймеры и тембры приближённые. Сохранение между запусками ADS пока недоступно.

[Новые сборки GVM](doc/brewgames-gvm-games.md): .hack//SIGN, Ragnarok Gaiden,
Mashimaro Fighting Matgo, Bukbeol, Fresh Fruit Tycoon, Fantasy Blue и вариант
Zzayo Zzayo Tycoon. Сохранены исходные ZIP и парные проверки управления.

[Сохранение платформы](doc/preservation.md) включает полные SDK 2.10/2.12,
эмуляторы, исходный Mobile C Reference 311 и ранние документы GVM.
[Проход 18](doc/game-hunt-pass18.md): сохранены 73 игровых ZIP SKT с Java-классами
и два примера исходников GVM; новых SGS этот проход не добавляет.

В 63 скачиваемых архивах сохранены сами файлы; есть реестр хешей всех членов.
[Daum и HandyGame](doc/korean-game-portals-pass20.md) добавляют архивные карточки
игр, ссылки на бета-тесты и таблицу телефонов GVM от января 2002 года.
[Softmax и m4leaf](doc/softmax-mobile-and-symbian.md) добавляют исходный
пакет Magna Carta M для KTF/BREW и результаты проверки коллекции Symbian 6/7.
Новый [проход GVM/GNEX](doc/gvm-gnex-firmware-player-followup.md) сохраняет
исходные образы Samsung E110/X350 и ещё один источник GVM2X.

[Дополнительные прошивки Samsung/LG](doc/korean-phone-preservation-pass16.md)
сохраняют 11 оригинальных архивов и игровые PXO. Отдельно получены
[169 файлов GLib и полная история проекта](doc/sinjisoft-glib-source-and-namu.md).
Эти исследовательские находки не добавляют новых поддерживаемых игр.

Каталог учитывает отдельные исторические сборки и демоверсии. В коллекцию
включены четыре [SGS с Mobaill](doc/mobaill-games.md),
[Zola из GVM Club](doc/gvm-forum-attachments.md) и пять
[SGS из приложений S60](doc/gnex-devices.md#symbian-s60).
Отдельно документированы [сохранённые S60-рантаймы](doc/s60-runtimes.md),
[исторические эмуляторы SDK](doc/gnex-emulators.md) и
[связь GVM с GNEX](doc/gvm-gnex-lineage.md).

У пяти сборок S60 проверены отдельные игровые действия. Внешние WAV/MIDI
их нативных оболочек к Reunion пока не подключены; исходные SIS и ресурсы
доступны отдельно на странице архивов.

## Что работает

| Режим                           | Проверенное покрытие                                                                                      |
| ------------------------------- | --------------------------------------------------------------------------------------------------------- |
| Веб: прямой запуск SGS          | 75 игровых сборок и утилита Mosquito, контейнеры v1/v2/v4/v36, ввод, таймеры, графика, сохранения и звук  |
| Веб: Swerve 3D                  | Independence Day: миссия с действующим управлением; `swv21brew.mod` включён                               |
| Веб и desktop: прошивка целиком | Kingston 2.12: холодная загрузка, меню, файловый менеджер и Hell Fire; восемь других ROM экспериментальны |
| Desktop: прямой запуск SGS      | Hell Fire, KPetris Beta, Ikaria ep2 и Godori                                                              |

«Работает» означает воспроизведённый игровой сценарий и содержательный ввод,
а не полное прохождение всех уровней. В [матрице совместимости](doc/compatibility.md)
сохранены результаты и сценарии. Телефонные профили относятся к веб-ядру;
они не объявляют полной эмуляции соответствующих телефонов.

## Запуск в браузере

Нужны **Node.js 22 или новее**, npm и современный браузер с WebAssembly.
После клонирования репозитория или распаковки исходников выполните из его корня:

```sh
git clone https://github.com/ALEXGREENCH/KPEX100-Reunion.git
cd KPEX100-Reunion
npm ci
npm run dev
```

Откройте `http://127.0.0.1:5174/` и выберите игру в библиотеке.
Все файлы коллекции уже доступны. При импорте дополнительных файлов известные
сборки распознаются по SHA-256 и получают настройки из каталога.
Для прямого запуска SGS используется включённая **Kingston 2.12**:

```text
743d0b9a377dc6a3f0a80b7816cee575ad2f8249643876367c4bfaac54ddd19a
```

Файлы, выбранные в браузере, обрабатываются локально. Сохранения хранятся в
IndexedDB отдельно для каждого приложения. Очистка данных сайта удаляет
локальное хранилище; используйте экспорт сохранений перед его очисткой.

Для простого запуска без инструментов форматирования достаточно
`node tools/serve.mjs`: обязательной компиляции JavaScript нет.
Открытие HTML через `file://` не поддерживается — Worker и WASM нужен HTTP.

### Проверка и восстановление коллекции

Для обычного запуска импорт не нужен. Python 3.11+ позволяет проверить весь
набор из 81 файла, а при необходимости восстановить их из отдельной распакованной папки
или предыдущей сборки Reunion:

```sh
python tools/assets.py verify
# Если локальные файлы отсутствуют:
python tools/assets.py import /path/to/originals
```

Импорт сверяет размеры и SHA-256, не меняет исходники и не заменяет изменённые
файлы назначения. `verify` требует всю коллекцию; `verify --allow-missing`
подходит для намеренно неполной локальной копии. Сборка по умолчанию проверяет
и включает весь набор из 81 файла.

| Материалы                                    | Файлов | Где находятся                            |
| -------------------------------------------- | -----: | ---------------------------------------- |
| Прошивки Kingston / Cenix                    |      9 | `web/data/firmware/`                     |
| SGS: 64 игровые сборки, Mosquito и 3 примера |     68 | `web/data/games/`                        |
| Быстрые состояния Kingston 2.12              |      3 | `web/data/states/`                       |
| Swerve 2.1                                   |      1 | `web/engine/vendor/swerve/swv21brew.mod` |

Хеши и профили записаны в [каталоге](web/data/catalog.json), происхождение
Swerve — в [отдельном отчёте](doc/swerve-provenance.json).

В девяти ROM готовые SGS не обнаружены. Игры в меню полного устройства
загружаются с виртуального FAT16-накопителя, куда Reunion помещает отдельные
файлы коллекции. [Отчёт и воспроизводимый сканер](doc/firmware-games.md).

## Сборка для GitHub Pages

```sh
npm run build
npm run preview
```

`site/` — готовая статическая сборка. Она работает как в корне сайта, так и по
адресу вида `https://OWNER.github.io/REPOSITORY/`. Сервер приложений не требуется.

После размещения исходников на GitHub выберите **Settings → Pages → Build and
deployment → Source → GitHub Actions**. Включённый workflow собирает и публикует
сайт при push в `main`; также доступен ручной запуск. Посетителям доступна
вся включённая коллекция. [Пошаговая настройка и проверка](doc/github-pages.md).

Для отдельного минимального сайта без коллекции предусмотрена команда
`npm run build:source-only`. В такой сборке посетитель добавляет ROM/SGS через
браузер. Обычные `npm run build` и workflow Pages собирают полную версию.

## Настольная версия

Нужен Python 3.11+ с Tkinter. Из корня репозитория, в PowerShell:

```powershell
python -m venv .venv
.venv/Scripts/python.exe -m pip install -r desktop/requirements.txt
.venv/Scripts/python.exe desktop/launch.py
```

При первом запуске библиотека desktop автоматически подготавливается из
включённого каталога `web/`. Ручной импорт для обычного запуска не нужен.
Зависимости и сборка Windows EXE описаны в [инструкции desktop](doc/desktop.md).
Возможности этой версии отличаются от веб-версии; телефонная совместимость
не переносится в Python автоматически.

## Управление в веб-версии

| Клавиши           | Действие                        |
| ----------------- | ------------------------------- |
| Стрелки           | Направления                     |
| `Z` / A           | OK / выбор                      |
| `X`, Esc / B      | Назад; CLR в телефонном профиле |
| Backspace         | CLR в телефонном профиле        |
| Enter / PLAY      | PLAY у K-PEX; ENTER у телефона  |
| Tab / MENU        | MENU у K-PEX; F1 у телефона     |
| `0`–`9`, `*`, `#` | Цифровая клавиатура телефона    |
| `Q` / `E`         | F1 / F2 телефона                |
| Пробел            | Пауза эмулятора                 |

В телефонном профиле **OK и ENTER различаются**. Большинство меню ожидает
`Z`/OK; для пропуска вступления могут потребоваться `*`, `#` или CLR. Если игра
опрашивает ввод по таймеру, удерживайте кнопку. Экранная клавиатура доступна
на выбранном корпусе, на смартфоне — под экраном. Громкость регулируется
ползунком 0–100% с шагом 5%; уровень запоминается. Библиотека и настройки
открываются поверх страницы. [Корпуса и проверка интерфейса](doc/web-interface.md).

В меню **Управление** можно заменить любое назначение, добавить альтернативы
и сохранить отдельную раскладку для игры. Поддержаны клавиатура, кнопки и колесо
мыши над LCD, кнопки и оси контроллеров через Gamepad API. Настройки сохраняются
в этом браузере. [Назначения, приоритеты и ограничения](doc/input-controls.md).

| Каталог       | Содержимое                                                                       |
| ------------- | -------------------------------------------------------------------------------- |
| `web/`        | Интерфейс браузера, Worker, ARM/GNEX-ядро и готовые WASM-компоненты              |
| `desktop/`    | Python-ядро, Tkinter-интерфейс и сборка Windows                                  |

| `tests/`      | Проверки веб-ядра и эталонные хеши                                               |
| `validation/` | Сценарии и отчёты проведённого исследования                                      |
| `vendor/`     | Исходники и лицензии сторонних компонентов                                       |

Начните с [архитектуры](doc/architecture.md), [аппаратной модели](doc/hardware.md)
и [инструкции инструментов](tools/README.md). В `doc` сохранены результаты
исследования **GNEX SDK 2.10/2.12**, Mobile C API, Swerve, XEOVIA и встраивания
игр Sinjisoft в плееры. Есть ссылка на [Sinjisoft Mobile C Reference Manual](https://cfile209.uf.daum.net/attach/165521104A3E87994E43CC),
хеши и разбор API. Для **LG CYON SH150A** отдельно отмечено: выпуск телефона
подтверждён LG, поддержка именно GNEX ещё не подтверждена найденным первичным
источником. [Библиография](doc/reference-index.md).

В [исследовании игр телефонных прошивок](doc/phone-firmware-games.md) собраны
Nokia, Samsung Anycall, LG, японские DoJa/BREW и плееры XEOVIA/Flash. Из пакета
Nokia 3410 извлечена Munkiki’s Castles; включён воспроизводимый Python-инструмент,
хеши и смещения. Документ отделяет проверенные файлы от ещё не полученных
прошивок и не расширяет заявленную совместимость Reunion.

## Разработка и проверки

```sh
npm ci
npm test
npm run format:check
npm run build
```

Обычные модульные тесты не зависят от оригинальных игр. Интеграционные проверки
используют включённую коллекцию и доступны сразу после клонирования:

```sh
python tools/assets.py verify
npm run test:integration
```

Интеграционные проверки исполняют настоящие ROM/SGS, проверяют Worker, аудио,
виртуальные файлы и сравнивают четыре игры K-PEX с нативными эталонами.
Сценарии можно повторять и расширять через [replay-sgs](doc/replay.md).
Правила оформления, проверки Python и порядок внесения изменений — в
[CONTRIBUTING.md](CONTRIBUTING.md).

## Ограничения

Веб-версия использует ускоренное исполнение с ограничением работы, проверенную
функцию очистки RGB565 и показ до 60 кадров/с. В восьми сравниваемых сценариях
вычисление ускорилось примерно в 1,6–4,6 раза с совпавшими кадрами и состояниями.
[Измерения, воспроизведение и ограничения](doc/web-performance.md).

Для [режима полной прошивки](doc/firmware-validation.md) отдельно проверены
холодные прогоны всех девяти ROM и ускорение Kingston 2.12. Быстрые состояния
возвращают сохранённый накопитель; холодный старт собирает диск из текущей коллекции.

Модель не тактово точная. DAI/DMA-аудио полного запуска прошивки, USB, SD, RTC
и вся периферия TCC76x ещё не завершены. Сложные 3D-сцены всё ещё ограничены
скоростью программного ARM-рендеринга. SMAF-синтез
приближённый; его тембры не являются дампом Yamaha ROM. Исторические сетевые
магазины и операторские службы не восстановлены.
