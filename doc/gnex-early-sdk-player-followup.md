# Ранние SDK: точные имена и поиск телефонного проигрывателя

6 ноября 2026 года сохранены 12 ответов архивной страницы загрузок GNEX Club,
новая полученная копия Windows GVM2X и материалы проверки телефонных пакетов.
**Установщики SDK 1.20/1.40 и самостоятельный GNEX-плеер для телефона пока не найдены.**

[Оригинальные файлы и ответы](../research/archives/GNEX-Early-SDK-Pages-and-GVM2X-Original.zip)
и [полный отчёт](../validation/early-sdk-player-preservation.json) доступны отдельно.
Файлы не исполнялись, формы входа и загрузок не отправлялись.

## SDK 1.40: имя теперь прочитано в оригинале

На [странице от 9 декабря 2004 года](https://web.archive.org/web/20041209135022id_/http://www.gnexclub.com:80/download/download.jsp)
скрипт присваивает полю `fname` **`GNEX_SDK_v1.40.exe`**. SHA-1 полученного
HTML совпадает с CDX. Это точное имя для поиска, а не восстановленный EXE.
Ранее было сохранено объявление 1.40, но не соответствующая версия страницы загрузок.

| Дата проверенного снимка | Имя GNEX в форме            |
| ------------------------ | --------------------------- |
| 2004-02-15               | `GNEX_SDK_V1.20.exe`        |
| 2004-04-15               | `GNEX_SDK_v1.22.exe`        |
| 2004-08-15               | `GNEX_SDK_v1.26_040809.exe` |
| 2004-10-15               | `GNEX_SDK_v1.27.exe`        |
| 2004-12-09               | `GNEX_SDK_v1.40.exe`        |
| 2005-02-13               | `GNEX_SDK_v1.41.exe`        |
| 2005-03-06               | `GNEX_SDK_v1.414.exe`       |
| 2009-04-11 и 2009-07-15  | `GNEX_SDK_v2.10.exe`        |
| 2009-08-15               | `GNEX_SDK_v2.12.exe`        |
| 2009-10-29               | `GNEX_SDK_V2.12.4.exe`      |

В марте 2005-го заголовок страницы записан как `1.4.1.4`, а имя файла —
`v1.414`. В октябре 2009-го заголовок остаётся `2.12`, тогда как имя файла
содержит `2.12.4`. Это разные поля источника; наличие новых дистрибутивов
или их соответствие уже сохранённым SDK 2.10/2.12 не установлено.

Страницы дают также варианты GVM SDK 1.52 с датами `031222`, `040329`,
`040809`, `040914`. Поздняя видимая ссылка ведёт к
`/file/GVM_SDK_v152_041018.zip`, хотя JavaScript продолжает называть `040914`.
Расхождение сохранено. Скрытый исходный `GNEX_SDK_Setup.exe` в форме —
общий placeholder, который скрипт заменяет; его нельзя объявлять именем 1.40.

Из 12 ответов **11 совпали с запрошенным CDX**. Запрос снимка декабря
2008-го вернул другие байты: они сохранены, но не используются как
подтверждение состава загрузок именно в 2008 году. Один успешный HTTP-ответ
не заменяет проверку дайджеста.

Точные suffix-запросы CDX для перечисленных целей вернули пустые массивы.
Прямые запросы двух поздних файлов не установили соединение. Это границы
конкретных проверок; отсутствие файлов во всём интернете не доказано.

## Две полученные копии GVM2X для Windows

Из [набора Internet Archive](https://archive.org/details/gvm2xemu) получены:

| Полученное имя                      |     Байты | SHA-256                                                            |
| ----------------------------------- | --------: | ------------------------------------------------------------------ |
| `2x_Cr256_Magic.exe`                | 1 056 768 | `2bcc2554605bc277a99ff1220db1a509f875c207221647f806d0fff3efd66f88` |
| `2x_Cr256_Magic_expired_remove.exe` | 1 056 768 | `c2c170b3c47cd99dc55fdadad31dd1927473b4362868205c5eb49eff96c60719` |

Размеры и SHA-1 обеих копий совпали с метаданными IA. Это PE32 x86;
все четыре файловые секции находятся внутри полученного файла.
Копии различаются только по смещениям `0x8c07` и `0x8c08`:
`ff ff` и `dd 00` соответственно. Название `expired_remove` не заменяет
исследование эффекта этих изменений; запуск и проверка снятия ограничений не проводились.

Копия `expired_remove` побайтно совпадает с ранее сохранённым вложением
Tistory. Другая копия добавлена отдельно; её имя без суффикса не доказывает
подлинность нетронутого выпуска производителя. Сохранены также семь
полученных изображений IA, включая окно About с надписью Version 2.06
(build 040328) и условия использования. Эти изображения скачаны из архива,
а не получены запуском EXE на компьютере исследователя.

Это **Windows-эмулятор**, не восстановленный проигрыватель для телефона.
Он не добавляет новую SGS в рабочий каталог Reunion.

## Телефонный GNEX: результат прохода

Повторно получен [пост автора об установке игр на SKY U130](https://wanggi.tistory.com/3).
Он сохраняет путь через WMRMake/BitPim, `wipi/sys/registry.dat`,
`wipi/sys/shared/wam/menu1.dat` и `wipi/ctn`. Вложенного бинарника
проигрывателя в полученной странице нет. Ранняя фраза о SGS/SKVM противоречит
поздней поправке самого автора: она не используется как спецификация формата.

Все 29 запросов исходных иллюстраций вернули HTTP 403. Сохранены именно
ответы об отказе и receipts, а не якобы восстановленные скриншоты.
Ограничения доступа не обходились. Ответ по текущему объявлению MS500
содержит оболочку приложения и не объявляется полным сохранённым постом
или пакетом GNEX.

[Первичный отчёт SK Telecom](samsung-s390-wipi-player.md) уже подтверждает,
что GNEX поставлялся как загружаемое WIPI-приложение. Следующая цель —
сам пакет установленного проигрывателя вместе с его записями регистрации.
Обёртка SGS/JAR, каталог игр и строка MIME не заменяют такой пакет.

## Независимое чтение страниц

Из корня репозитория:

```sh
python tools/inspect-gnex-sdk-pages.py research/archives/GNEX-Early-SDK-Pages-and-GVM2X-Original.zip
```

Команда использует стандартную библиотеку Python, сверяет SHA-256 исходных
HTML с receipts и SHA-1 с CDX, затем выводит буквальные имена из форм и
прямых ссылок. JavaScript страниц не выполняется. В архиве есть манифест
всех файлов; оригиналы и производные отчёты разделены.

Материалы сохраняют исходные права. MIT Reunion относится только к новому
инструменту анализа и не перелицензирует исторические EXE, HTML или изображения.
