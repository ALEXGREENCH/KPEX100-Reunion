# Внутреннее устройство Emulator.exe из SDK 2.12

Повторный разбор 6 ноября 2026 года. Изучен исходный x86 PE на 1 228 800
байт, SHA-256 `81ed4493f5b50748b332f63476634bd7ba82c96f059e816b741eb4bb4f918e0a`.
Он уже сохранён в [комплекте Windows-эмуляторов](gnex-emulators.md).
Это разбор программы, а не только API-руководства. Установщик, DLL и EXE
не запускались. [Инструкции, границы и хеши участков](../validation/sdk-emulator-internals.json).

## Загрузка и два исполнителя

В `0x442D25` загрузчик сравнивает версию SGS с 4. Современная ветка читает
`0x80` байт заголовка и устанавливает `0x518CDC = 1`; старая читает `0x68`
и записывает 0. После этого обработчики расходятся. Нельзя считать все
GVM/GNEX одним интерпретатором только из-за общей оболочки Emulator.exe.

Современный обработчик KEYPRESS `0x41B790` записывает значение в переменную
по указателю `0x519B24`, читает точку входа из заголовка `+0x28` и вызывает
`0x41B6C0`. Этот цикл сбрасывает три индекса стеков в −1, прибавляет
точку входа к базе скрипта `0x518C94`, читает 16-битные операции и
вызывает обработчики через таблицу `0x518E64`. Шаг чтения операции — два
байта. Это не означает, что значения этой VM имеют разрядность 16 бит:
здесь видно именно кодирование операции, а не размер всех её операндов.

Таблица syscall заполняется **инструкциями инициализации**, а не лежит
готовым массивом указателей в файле. В `0x41D070..0x41E5B0` инструмент
восстанавливает 538 непосредственных присваиваний в таблицу `0x53B3C4`.
Это частичная карта: другие формы присваивания и работоспособность функций
этим не проверены. Имена 908 функций отдельно получены из
[MASM/MCC](tools-guide.md#каталог-системных-функций).

## Ввод и очередь событий

Проверенная [цепочка отпускания](kpex-key-release.md) переводит индекс
кнопки 47 через `0x50F254` в `255`. В `0x443BB8` современная ветка передаёт
это значение в VM, старая явно отбрасывает его.

Диспетчер `0x442820` сначала вызывает `0x448620`, затем проверяет флаг
исполнения `0x515AC8`. При уже работающем обработчике событие остаётся в
очереди; при свободном VM оно извлекается через `0x4485E0`.

Очередь — кольцо из десяти записей по 28 байт, начало `0x5E85C0`.
Индексы записи/чтения — `0x5E86D8` и `0x5E86DC`. Условие заполнения
`(write + 1) % 10 == read` оставляет одну позицию пустой: одновременно
хранятся максимум девять событий. Push копирует семь 32-битных слов и
возвращает 0 при заполнении. Политика вызывающего кода при отказе push
здесь полностью не восстановлена. Переносить это ограничение в браузер
без подтверждения поведения ARM-прошивки пока оснований нет.

## Таймеры: обнаруженное отличие SDK

Три обработчика `SetTimer/1/2` по адресам `0x421D80`, `0x421DC0`,
`0x421E00` передают номер канала 0/1/2 в `0x42FEA0`. Признак повторения
берётся младшим байтом; задержка — отдельным 32-битным значением.

`0x42FEA0` **не передаёт в Windows задержки меньше 10 мс**, включая ноль.
Это не округление до 10: функция возвращается до изменения host-таймера.
Обработчик syscall перед этим уже обновил свои глобальные значения,
поэтому нельзя упрощать поведение до единственного общего поля delay.

`ResetTimer/1/2` — отдельные функции: через `0x42FEF0` они передают нулевую
задержку в `0x407B90`. Здесь положительная задержка вызывает импорт
`0x4B15F0`, нулевая — `0x4B15EC`; им соответствуют SetTimer и KillTimer
в таблице импорта PE. Идентификатор Windows-таймера — `0x1000 + channel`.
Обработчики `0x407C2B..0x407CFA` проверяют повторяемость и останавливают
одноразовый таймер **перед** callback, позволяя обработчику поставить новый.

Это новая конкретная цель для сверки SDK, ARM и аппаратных профилей.
Текущее принятие положительных задержек в Reunion этим проходом не менялось:
перенос особенностей Windows SDK на все реальные телефоны и K-PEX требует
независимого эталона, как уже сделано с отпусканием кнопки.

## Повтор анализа

```sh
python -m pip install capstone==5.0.7
python tools/inspect-sdk-emulator.py path/to/SDK-2.12/Emulator.exe --output ../sdk-internals.json
```

Инструмент проверяет точный размер и SHA-256, разбирает PE, дизассемблирует
20 ограниченных участков и проверяет полные границы инструкций. Неизвестный
файл и существующий выходной JSON отвергаются. Capstone нужен только этому
исследовательскому инструменту, а не эмулятору или обычной сборке сайта.

[Разбор raw MA1 и нативный эталон](gvm-ma1-native-reference.md): 820 слов,
перехваченные MIDI/таймеры SDK и отдельное представление регистров Yamaha.
FM-синтез raw MA1 пока не реализован.
