# Поиск игр внутри прошивок

В девяти ROM из этой коллекции **готовых SGS-контейнеров не найдено**.
Проверено 63 003 136 байт и 2 336 662 возможных начала заголовка. Проверка
охватывает форматы SGS v1/v2/v4/v36 в обычном виде и с XOR `0xA5`.
[Машинный отчёт](../validation/firmware-games-scan.json) содержит SHA-256 каждого
ROM, размеры, число проверенных смещений и положительные контрольные примеры.
На момент этой проверки каталог содержал 38 SGS.

## Откуда игры в меню запущенной прошивки

При запуске полного устройства Reunion создаёт виртуальный FAT16-накопитель и
помещает в его каталог `GAME` отдельные SGS из общей коллекции. Это делают
[веб-модель диска](../web/engine/disk.js) и
[настольная модель диска](../desktop/kpex/disk.py). Ресурсные секции ROM копируются
в другие, служебные секторы того же виртуального накопителя.

Три включённых быстрых состояния восстанавливают свои снимки диска с четырьмя
играми: Godori, HellFire, Ikaria и KPetris. Чтобы меню увидело всю доступную
коллекцию и добавленные SGS, в веб-версии выберите холодный старт.

Оригинальная Kingston 2.12 открывает выбранную игру как файл. В исследованном
ARM-коде по файловым смещениям `0x53F34–0x53F48` формируется путь `GAME\` с
именем выбранного файла, по `0x53F64` вызывается запуск движка, а по `0x4187C`
файл открывается через родную файловую систему. Чтение и XOR-декодирование
находятся по `0x3CDEC`; проверка версий SGS — по `0x41924–0x41950`.
Адреса относятся к неизменённому Kingston 2.12 с SHA-256
`743d0b9a377dc6a3f0a80b7816cee575ad2f8249643876367c4bfaac54ddd19a`.

Таким образом, меню прошивки показывает игры с подготовленного накопителя.
ROM предоставляет загрузчик, интерпретатор GNEX, графические функции и ресурсы
интерфейса. Подробности размещения ресурсов и проверенного запуска — в
[описании аппаратной модели](hardware.md).

[Шесть имён с фотографии Kingston](kingston-observed-games.md) сопоставлены
с историческими каталогами; это отдельное наблюдение по одному накопителю.

## Повторить проверку

Нужен Python 3.11 или новее; сторонних библиотек сканер не требует.
Из корня репозитория:

```sh
python tools/scan-firmware-games.py --check-controls --output scan.json
```

Без путей на входе проверяются девять ROM из каталога. `--check-controls`
дополнительно проверяет 38 исходных SGS: сканер должен найти ровно один
контейнер в каждом файле. Все 38 контрольных примеров прошли; поддержаны и
файлы с внешним 32-байтовым заголовком. Имена, хеши и смещения контрольных
примеров сохраняются в отчёте.

Можно проверить другой образ или несколько файлов и извлечь найденное:

```sh
python tools/scan-firmware-games.py image.rom --output image-scan.json --extract extracted-games
```

`--output` требует новое имя файла. Каталог `--extract` должен быть новым или
пустым. Существующие извлечённые файлы не заменяются. Исходные образы открываются
только для чтения; один входной файл ограничен 64 МиБ. Без `--output` JSON
выводится в стандартный поток.

## Что считается кандидатом

Для каждого подходящего байта версии проверяются границы и порядок секций,
размеры дескрипторов, обработчики событий, объём начальных переменных и полное
покрытие объявленного блока ресурсов. Сканирование проверяет и невыровненные
смещения. Для отсеивания случайных совпадений кандидат должен иметь START,
хотя бы одну переменную, хотя бы один ресурс и не менее 16 байт байткода.
Это консервативный поиск игровых контейнеров; минимальная программа без
ресурсов или переменных под эти условия не попадает.

В отчёте различаются смещение тела SGS и начало распознанной внешней обёртки.
Для сравнения вариантов используется SHA-256 декодированного тела: внешняя
32-байтовая обёртка и XOR сами по себе не создают новую игру. При извлечении
сохраняется первая найденная исходная последовательность байтов каждого
уникального тела, включая распознанную обёртку и исходный XOR.

Конец извлечения определяется таблицей ресурсов. Произвольные добавочные
данные после неё нельзя надёжно отделить от остального образа: сканер их
не угадывает. В частности, некоторые исходные SGS используют дополнительные
файловые данные после объявленного тела. Поэтому корректная структура
извлечения ещё не подтверждает полноценный запуск приложения.

Нулевой результат не исключает нативные ARM-игры, неизвестное сжатие или
другую упаковку. Он относится к описанным форматам и девяти проверенным ROM.

## Проверки инструмента

```sh
python -m pytest tests/python/test_firmware_scan.py -q
```

Синтетические тесты проверяют все четыре версии, обе кодировки, внешнюю
обёртку, поиск внутри другого файла, повреждённые границы, повторяющиеся
представления одного тела и отказ от перезаписи. Они не требуют оригинальных
игр или прошивок. Проверка реальных положительных примеров выполняется
отдельным флагом `--check-controls`.
