# Воспроизводимые инструменты исследования

Команды ниже запускаются из корня репозитория. Для двух SDK-инструментов нужен Python 3.10 или новее; внешние Python-пакеты не требуются. Для чтения вложенных MSI/CAB нужен 7-Zip. Node.js нужен для SGS-инструментов и воспроизведения игровых сессий.

Инструменты читают установщики и PE-файлы как данные. Они не вызывают `msiexec`, не загружают DLL и не исполняют содержащийся в них код. Исходные SDK и руководства не входят в набор инструментов и не скачиваются им автоматически. ROM и SGS игровой коллекции уже включены в репозиторий и проверяются по хешам.

## Статическая распаковка GNEX SDK

`tools/sdk-static.py` поддерживает ровно два исследованных ANSI-контейнера InstallShield:

| Исходник                                                     | SHA-256                                                            |
| ------------------------------------------------------------ | ------------------------------------------------------------------ |
| [GNEX SDK 2.12](https://archive.org/details/gnex_sdk_v2.12)  | `87d852091c8d25134d6b57bf14e8745b5e99f6c6277fdb56bff801b1ff0fd3a7` |
| [GNEX SDK 2.10](https://archive.org/details/gnex-sdk-v-2.10) | `075f010557029a53a5c7e01fc7f492e4236a26b8edb019fcd7193d0719a0dd19` |

Сохраните выбранный файл в отдельном исследовательском каталоге `research-input`. Для получения только списка файлов и хешей:

```powershell
python tools/sdk-static.py research-input/GNEX_SDK_v2.12.exe
```

Для извлечения восьми файлов внешнего контейнера:

```powershell
python tools/sdk-static.py research-input/GNEX_SDK_v2.12.exe --extract research-work/sdk212-outer
```

Каталог назначения должен быть новым или пустым. Рядом с извлечёнными файлами создаётся `receipt.json`: смещения, размеры, хеши, идентификатор исходного комплекта. Неизвестный хеш, повреждённые границы контейнера, неподдерживаемый формат имени или повторный путь приводят к ошибке. Существующие файлы не заменяются. Версия 2.10 используется такой же командой с её именем файла и отдельным каталогом назначения.

Затем можно извлечь только поток CAB из MSI и его содержимое, всё ещё без установки:

```powershell
& 'C:/Program Files/7-Zip/7z.exe' e 'research-work/sdk212-outer/GNEX SDK.msi' Data1.cab '-oresearch-work/sdk212-msi'
& 'C:/Program Files/7-Zip/7z.exe' x 'research-work/sdk212-msi/Data1.cab' '-oresearch-work/sdk212-files'
```

Это даёт 255 файлов SDK 2.12. Полные установщики и извлечённые материалы остаются локальными исследовательскими входами. Описание контейнера и алгоритма сверялось с [ISx](https://github.com/lifenjoiner/ISx), MIT, Copyright 2017 lifenjoiner; Python-реализация выполнена отдельно. `pe_reader.py` — небольшой проверяющий границы PE32-ридер, общий для двух инструментов.

## Каталог системных функций

`tools/sdk-syscalls.py` воспроизводит [sdk-syscalls.json](sdk-syscalls.json) из **SDK 2.12**:

```powershell
python tools/sdk-syscalls.py --masm research-work/sdk212-files/MASM_GNEX.exe --mcc research-work/sdk212-files/mcc_GNEX.exe --output research-work/sdk-syscalls.json
```

Файл результата должен отсутствовать. Проверяются точные хеши:

| Вход            | SHA-256                                                            |
| --------------- | ------------------------------------------------------------------ |
| `MASM_GNEX.exe` | `c9dd8612c392b0a1f9189b838b529157c1235f48e344e781fdb4c47ff3b5530a` |
| `mcc_GNEX.exe`  | `a02ffd612a4a242852f35a1fc0fc4bdf1911c0a07375a75955822ce5629f996f` |

Системные индексы берутся из массива 908 имён MASM по VA `0x41DE38`. Сигнатуры компилятора находятся по файловому смещению `0x266A4`, шаг 52 байта. Сопоставление выполняется **по имени**: поздние номера компилятора не равны номерам syscall. Две отключённые функции `//_GetCenterPoint` и `//_SetCenterPoint` сохранены без сигнатуры, поскольку в компиляторе их имена отличаются. Коды типов остаются числовыми свидетельствами бинарной таблицы; они не переименовываются в недоказанные C-типы.

## Информация об SGS

Существующий `sgs-info.mjs` использует разборщики того же проекта. Он сообщает версию, точки входа, секции и ресурсы без исполнения игрового кода:

```powershell
node tools/sgs-info.mjs research-input/game.sgs --json
node tools/sgs-info.mjs research-input/game.sgs --resource 0 --out research-work/resource-0.bin
```

Выбранный ресурс создаётся исключительно как новый файл. Результат содержит SHA-256 ресурса. Тип ресурса и первые байты нужно интерпретировать вместе: например, старший бит звукового типа сам по себе не доказывает сжатие.

## Проверки этого набора

[validation/sdk-tools.json](../validation/sdk-tools.json) фиксирует проверку на обоих исходных установщиках: все 16 извлечённых членов совпали по SHA-256 с независимой первоначальной распаковкой. Вновь полученные 908 записей каталога полностью совпали с сохранённым результатом исследования. Повторное извлечение в занятый каталог и ошибочный PE-вход отклонены без замены исходных файлов. Ни один установщик при проверке не запускался.

## Повтор игровых сессий

`replay-sgs.mjs` исполняет исходный SGS в ARM-эмуляторе, сохраняет PNG после каждого действия и итоговую диагностику. Для запуска используются включённые оригинальные ROM/SGS, а для 3D — включённый проверенный Swerve-модуль. Это исполняющий инструмент; описанное выше правило статического чтения установщиков относится к SDK-инструментам.

```powershell
node tools/replay-sgs.mjs gnex26_independence_day_3d validation/independence-actions.json validation/swerve-replay
```

Действия `['key', code]`, `['hold', code]`, `['release', code]` задают короткое нажатие, удержание и отпускание. `['tick', count]` использует реальные виртуальные дедлайны TimerScheduler. Отдельный режим `['manualTick', count, deltaMs]` прибавляет явно указанное виртуальное время и один раз вызывает каждый установленный таймер на шаг. Он применяется в сохранённом 3D-прогоне для ускорения вступления и **не означает** исполнение всех пропущенных периодов таймера. В итоговом JSON это явно обозначено полем `clockMode`; текст SGS при этом не меняется. Допустимый ручной шаг — от 1 до 10 000 мс.
