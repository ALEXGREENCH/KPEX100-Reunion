# Kingston 2.12: GetTick внутри callback

На модели ARM оригинальной Kingston 2.12 `GetTick(0)` и `GetTick(9)` вернули по 20 мс до и после длинного `EVENT_TIMEOUT`. Между точками наблюдения прошли 17 705 204 ARM-инструкции и около 122,95 мс по модели тактирования. Счётчик IRQ вырос с 2117 до 2167. Поэтому неизменившийся `GetTick` в этом опыте нельзя объяснить отсутствием всех IRQ.

Это ограничивает оптимизацию SGS: выход из долгого обработчика по разнице `GetTick` не обеспечил ограничение его длительности. Частоту физического устройства и поведение других прошивок опыт не устанавливает. Причина внутри реализации API отдельно не локализована.

## Воспроизведение

Из корня полной сборки Reunion, с Node.js 22 или новее:

```sh
node tools/probe-kingston-callback-clock.mjs --output callback-clock.json
```

Выходного файла ещё не должно существовать. Инструмент загружает неизменённую прошивку, создаёт FAT16 с `TICK.SGS`, проходит меню и наблюдает вход и возврат диспетчера GNEX по адресу `0x20049298`. Перед исполнением сверяются SHA‑256 прошивки и пробного SGS. Наблюдатели не меняют результаты API и состояние ARM.

Проба сбрасывает два счётчика, запускает таймер 20 мс и в первом callback выполняет 50 тысяч целочисленных итераций между чтениями `GetTick`. Маркеры начала и завершения, результат цикла и число итераций остаются в массиве из 17 слов. После завершения таймер отключается. [Mobile C](../tools/fixtures/kingston-callback-clock/clock.mc) · [SGS](../tools/fixtures/kingston-callback-clock/clock.sgs) · [Журнал](../validation/kingston-callback-clock.json)

| Файл          | SHA‑256                                                            |
| ------------- | ------------------------------------------------------------------ |
| Kingston 2.12 | `743d0b9a377dc6a3f0a80b7816cee575ad2f8249643876367c4bfaac54ddd19a` |
| Пробный SGS   | `8c79353af9698c1a7259415894271b0c31a8323f41f4c51bb9c1b4a5a4502573` |
| Mobile C      | `5b745c45e908329d9298e842c80f5210930a56579bdbaad07d066906be11e22f` |

Исходник собирается сохранённым GNEX SDK 2.12 через `build_sgs` и `encode_kpex` из `demos/sgs_build.py`. Для повторного исполнения SDK не нужен. Исходник и пробный SGS — код Reunion под MIT; оригинальная прошивка в исследовательский комплект не вложена.

Увеличенный пакет Z80-инструкций Petris и адаптивный вариант с ограничением через `GetTick(9)` пропустили импульс Play длительностью около 80,56 мс на модели. Состояние CPU/RAM и графика в прямом прогоне у таких вариантов совпадали с базовым; этого оказалось недостаточно для проверки штатного ввода. Эти варианты не включены в опубликованный лаунчер. [Журнал неудачных импульсов](../validation/petris-scheduler-experiments.json). Один импульс в одной фазе не определяет вероятность пропуска: для сравнения вариантов нужен отдельный проход с разными моментами нажатия.
