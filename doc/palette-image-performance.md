# Пакетный вывод палитровых изображений

Ускорен проверенный цикл Kingston 2.12 для обычных палитровых изображений
1/2/4/8 бит. Ветка работает от 128 пикселей по ширине; мелкие изображения,
масштабирование, эффекты, неоднозначные адреса и малый бюджет сохраняют
оригинальное исполнение. ROM, SGS, ARM WASM и Swerve не менялись.

[Измерения, последовательности кадров и сравнение состояния](../validation/palette-image-performance.json).

## Измеренный результат

Battle Armor: исходный сценарий входа, затем 240 TIMEOUT, три измерения
после одного прогрева. Медиана обработки гостевых событий — **9,40 с
вместо 10,04 с**, на **6,4% меньше времени** относительно `97e02c0`.
Совпали кадры, вся последовательность их хешей, события, syscalls,
таймеры и виртуальное время. Использована текущая политика отпускания
кнопок, подтверждённая оригинальной прошивкой.

У восьми дополнительных игр сравнение старого и нового ускоренного режима
также дало одинаковое состояние. В новом режиме дополнительно совпали
результаты точного ARM и ускоренного исполнения. Замеры Node/V8 не включают
показ в Chrome, сеть и синтез звука; они не задают прирост FPS для всех сцен.
Малые пороги давали смешанные результаты, поэтому выпуск использует 128.

Battle Armor после того же prelude прошёл ещё 600 000 виртуальных мс с
seed 67890: 5 602 операции, `idle`, без ошибки. Воспроизведение случайного
зависания в гараже или на выходе остаётся незакрытой задачей. Этот прогон
проверяет обработчики, а не прохождение всей миссии.

## Нативный эталон и защита

Проверяются хеш ROM и исходные ARM-байты участков `0x2004e4c4`–`0x2004e7b4`.
Ускорение начинается до установки счётчика строки. Из подтверждённого
контекста читаются глубина пикселя, маска, прозрачный индекс, шаги строк
и границы. Для обычного непрерывного случая оставшиеся строки одного
вызова обрабатываются вместе; последний внешний цикл и эпилог остаются ARM.

Высота берётся из подписанного поля объекта `+0x4e`, stride — из `+0x25e`.
Неоднозначные поля и пересечения входа, палитры, выхода, стека и читаемых
полей объекта исключают пакет нескольких строк. Сохраняются прозрачные
пиксели и промежутки между строками. Слишком малый watchdog-бюджет
не допускает обхода его границы. Остановка внутри ядра не пропускается.

Сравнение с оригинальным кодом проверяет все ARM-регистры, CPSR/SPSR,
стек, входные данные, палитру, результат и соседние байты. Есть случаи
смещения по битам, пропуска строк, прозрачности, перекрытий, предельной
ширины/высоты, нестандартных параметров и остановки внутри функции.

Unicorn 1.0.3 по-разному сообщает BLOCK при включённом счётчике инструкций
и без него: 26 инструкций внешнего fall-through не получают отдельного
уведомления в counted-режиме. Сохраняются оба наблюдаемых нативных счётчика;
они не заменены общей выдуманной моделью. CPU временно хранит конечный
адрес и вид текущего запуска и восстанавливает их даже после исключения.
При явном архитектурном бюджете VM продолжает использовать точный путь.

## Повтор

Нужны две копии репозитория: эталон `97e02c0` и новая ревизия. Из новой:

```sh
node --test --test-concurrency=1 tests/rom-accelerators.test.mjs
node tools/benchmark-web.mjs --root ../baseline --games battle-armor --prelude validation/kingston-naver-replays/battle-armor.json --execution guarded --runs 3 --warmups 1 --frames 240 --output ../before.json
node tools/benchmark-web.mjs --games battle-armor --prelude validation/kingston-naver-replays/battle-armor.json --execution guarded --runs 3 --warmups 1 --frames 240 --output ../after.json
node tools/benchmark-web.mjs --runs 1 --warmups 0 --frames 60 --execution both --output ../game-equivalence.json
node tools/stress-kpex.mjs --game battle-armor --minutes 10 --seed 67890 --prelude validation/kingston-naver-replays/battle-armor.json --output ../battle-stress.json
```

Для архитектурных трасс и поиска расхождений сохраняется `fastExecution: false`.
