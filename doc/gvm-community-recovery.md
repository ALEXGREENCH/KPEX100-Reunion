# Вложения GVM Club: WI-TOP, Hellfire и Mobile C

В сохранённых вложениях корейского форума GVM Club получены два исходных
ZIP-комплекта WI-TOP и один исходник Mobile C. Для каждого загруженного
файла SHA-1 совпал с записью CDX; дополнительно сохранён SHA-256.
[Адреса, размеры и результаты проверки](../validation/gvm-community-source-recovery.json).

## Комплекты WI-TOP

Вложения [№53, `witop2.zip`](https://web.archive.org/web/20020623052620id_/http://www.gvmclub.com:80/boardcomm/board.cgi?bd=no&j=dl&i=53&c=14)
и [№49, `witop.zip`](https://web.archive.org/web/20020623052226id_/http://www.gvmclub.com:80/boardcomm/board.cgi?bd=no&j=dl&i=49&c=18)
занимают 4 910 898 и 4 936 268 байт. Обе ZIP-проверки CRC прошли.
Имя файла восстановлено из HTTP `Content-Disposition`, поэтому эти
вложения не обозначаются как неизвестная версия полного GVM SDK.

В каждом комплекте 11 файлов: руководство по предоставлению GVM/SK-VM
через WI-TOP от 19 февраля 2002 года, примеры GVM и SKVM, иконки и
конвертер изображений с инструкцией. Версии комплекта конвертера различаются.
Пример SKVM — Java HelloMIDlet; он учитывается отдельно от SGS.
Старые Windows EXE не запускались.

Оба архива содержат одинаковый `Sample File/GVM/0007501FFFFFFFF.sgs`:

| Параметр        | Значение                                                           |
| --------------- | ------------------------------------------------------------------ |
| Внутреннее имя  | Hellfire                                                           |
| Формат и размер | SGS v1, 24 502 байта, без оболочки и XOR                           |
| SHA-256         | `37a3310b683e47b90e070e8772ac3ad267be172d11799f1168a2350fe448eec8` |
| Структура       | 52-байтный заголовок, 83 описателя переменных, 50 ресурсов         |
| События         | START `0x63a`, TIMEOUT `0x652`, KEYPRESS `0x728`                   |
| Профиль из INS  | GVM 1.0, 120×100, Color-Type 16, MA2/MA3                           |

Таблица ресурсов полностью покрывает файл до EOF. Сохранены также исходные
INS на 504 байта и RES на 1 027 байт. INS указывает другие имена SGS/RES,
чем фактические имена вложений; это несоответствие оставлено как в оригинале.
Поля срока действия INS сами по себе не объясняют результат исполнения.

Повторяемый [сценарий](../validation/replay-witop-hellfire.json) с профилем
из INS останавливается при START: оригинальный Kingston-интерпретатор
возвращает исключение 15, legacy opcode `0xba`. Сообщаемый PC — `0x651`,
после чтения байта операции по `0x650`. Изображение игрового процесса не
получено. Этот образ сохранён для исследования и не добавлен в каталог
поддерживаемых игр. Байткод не изменялся.

После извлечения оригинального SGS из комплекта проверка воспроизводится так:

```sh
node tools/replay-sgs.mjs --file /path/to/0007501FFFFFFFF.sgs validation/replay-witop-hellfire.json /path/to/new-output
```

Ожидаемый текущий результат — указанная ошибка и код завершения 1.
Родство названия с другими выпусками Hellfire не доказывает совпадение их кода.

В дальнейшем оригинальный MASM SDK позволил установить имя этой операции:
`0xba` — **LockChatMode**. Современный исходный пример Hellfire из SDK
содержит закомментированный вызов этой функции. Это не основание пропускать
команду без обработки аргумента и состояния; runtime в этом проходе не менялся.
[Статические таблицы и подтверждение эмиссии опкода](gnex-sdk-internal-sources.md#legacy-команды-0xba-0xbb-и-0xc4).

## Исходник HiBaby.mc

[Прямое вложение старого форума](https://web.archive.org/web/20030903132834id_/http://gvmclub.com:80/board/free/include/tbl_board_free/files/php11syE8/HiBaby.mc)
содержит 1 329 байт исходного Mobile C, SHA-256
`d5624ceb9d2df016ec917471a8396ae7e5c97478625348b6e866e1e8ed5fa777`.
Файл сохранён в исходной кодировке CP949 и с исходными переводами строк.

В заголовке объявлены SCRIPTVER 2, IMAGETYPE 12 и имя HiBaby:hb1.0.
Код инициализирует строки, выводит экран и обрабатывает `EVENT_RSRECEIVE`
через `swData`, `swRsRcvBuf`, `GetByte` и `PutChar`. Это пример работы
с последовательным интерфейсом. Компиляция и обмен с реальным телефоном
не проверялись.

Следующая попытка той серии получить UI_Example.mc вернула HTTP 429;
запросы были остановлены. В последующем проходе оригинал удалось получить
и проверить: [ранние руководства и исходные примеры](gvm-early-service-guides.md).
Ещё один проход восстановил [13 форумных вложений, включая файтинг с SGS](gvm-forum-attachments.md).
Оригинальные комплекты и исходники остаются
историческими сторонними материалами; лицензия Reunion их не перелицензирует.

Связанные первоисточники: [руководства и таблицы телефонов 2002–2003 годов](gvm-historical-handsets.md).
