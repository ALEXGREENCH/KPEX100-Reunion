# Swerve 3D: настоящий ARM-движок в браузере

Reunion исполняет оригинальный `swv21brew.mod` версии 2.1.0.364. SGS выполняется исходным ARM-интерпретатором GNEX из Kingston 2.12; трёхмерные вызовы передаются второму ARM-процессору, который исполняет код Superscape. Геометрия, анимация, выбор камеры, M3G-загрузчик и RGB565-растеризация выполняются этим оригинальным модулем.

Модуль размером 273 188 байт имеет SHA-256 `1e76412e158bc3948bf6ad173b181368e0f0d554d6b0e1488a29402d96b0cdab`. Происхождение и цепочка архивов находятся в [swerve-provenance.json](swerve-provenance.json). Его неизменённый файл включён в репозиторий и обычную сборку Pages по пути `web/engine/vendor/swerve/swv21brew.mod`. Это собственнический бинарный модуль, а не исходный код Reunion и не компонент, получивший лицензию GPL вместе с Unicorn. Публичный проект [khvcemu](https://github.com/khrecast/khvcemu) послужил первичным указателем на BREW-модуль, таблицу системных helpers и класс расширения.

## Исполнение

- `web/engine/m3g-native.js` создаёт отдельный экземпляр Unicorn 1.0.3 ARM/WASM. Это необходимо: вложенный запуск двух CPU в одном старом WASM-модуле повреждает контекст внешнего CPU. Отдельный модуль проверен тестом вложенных ARM-вызовов.
- Образ загружается по `0x04000000`, таблица BREW helpers — через указатель по `base-4`. Куча находится в `0x06000000..0x06ffffff`; отдельные области отведены для helpers, передаваемых массивов и ARM-стека.
- `AEEMod_Load` создаёт модуль BREW. Его `CreateInstance` с class ID `0x0102bbfc` возвращает Swerve engine. CPU работает в ARM User mode `CPSR=0x10`, как приложение BREW; оригинальный код сам пропускает привилегированное обслуживание кэша.
- Поддерживаются реально используемые malloc/free/realloc, операции с памятью и минимальное окружение приложения. Неизвестный BREW helper вызывает явную ошибку. Код модуля не патчится.
- `web/engine/swerve.js` переводит параметры GNEX в BREW ABI. `web/engine/m3g-api.js` содержит 71 сигнатуру из игрового сценария и проверенные смещения оригинальных функций. Неизвестный вызов не получает придуманного успешного результата.

Native vtable engine имеет методы AddRef, Release, GetVersion, GetPixelFormat и CreateObject. Factory ID не равен типу объекта: например Graphics3D имеет factory ID 8 и внутренний type 25. `getHandleType` вызывает настоящий виртуальный метод объекта. World имеет внутренний type 22.

## Загрузка и указатели

Оба файла Independence Day 3D читаются непосредственно из приложенного к SGS виртуального файлового раздела. `gnex.m3g` имеет 6 002 байта; `scene.m3g` — 128 595 байт и идентификатор SWERVE, включая нестандартный объект type 23. Оба файла загружаются без изменения содержимого и возвращают по одному World.

BREW Loader slot 3 принимает `(loader, byteLength, bytePointer)`. Slot 5 возвращает число корней через выходной указатель; slot 6 получает корневой объект по индексу. Интерфейс GNEX `swv_loader_load(filename, outCount)` отличается: он возвращает **encoded pointer на динамический массив корневых handles**, а число корней записывает через второй аргумент. Эта семантика проверена по исходному SGS: последующие инструкции разыменовывают возвращённый массив и передают его элемент `object3d_animate`.

Для динамических GNEX int32-массивов используются исходные дескрипторы `0x20b41e1c + slot*12`: адрес, количество элементов и флаг продолжения. Указатель имеет вид `0x80000000 | (slot<<20) | elementIndex`. Все float-параметры переносятся как исходные 32-битные слова, без преобразования через JavaScript Number.

Проверенные размеры: position/translation/scale — 3 float; orientation — 4; projection parameters и scale/bias — 4; ray — 6. `transformPoints` принимает **число float**, кратное четырём, а не число векторов. Выходные BREW boolean записываются одним байтом, поэтому мост обнуляет их полный GNEX int32 перед вызовом. Для UserParameter сначала запрашивается фактическая длина: оригинальный модуль игнорирует переданный максимальный размер и способен скопировать весь сохранённый параметр.

## Кадр и управление

`setBackBufferData` имеет ABI `(graphics, width, height, pitchBytes, pixels)`. Нативный рендерер записывает little-endian RGB565; проверочный зелёный фон даёт `e0 07` в каждом пикселе. Нулевые pitch/resource, которые передаёт сама игра, выбирают LCD GNEX с pitch `width*2`. Мост хранит копию RGB565 в памяти Swerve и переносит результат обратно в LCD-память GNEX после renderWorld. Итоговое изображение проходит общий путь показа кадра Reunion.

Клавиши передаются исходному SGS и маске удерживаемых клавиш. SGS v4/v36 отправляет `KEYPRESS 0xff` при отпускании: это подтверждено руководством GNEX и обработчиком WM_KEYUP оригинального SDK. Без этого события игра может продолжать стрельбу после отпускания кнопки. В SGS v1/v2 событие фильтруется. После независимой [проверки оригинальной прошивки](kpex-key-release.md) отпускание включено также в общем профиле K-PEX.

В Independence числовая `5` выбирает пункт меню, стрелка вниз переводит подтверждение с Cancel на Continue, повторная `5` подтверждает выбор. После завершения перехода на экран инструктажа `5` запускает миссию. `1` управляет тягой, `4`/`6` — поворотом, `5` — ракетами. Наиболее важный проверенный результат ввода — изменение показателя тяги и расход одной ракеты в уже запущенной миссии.

## Проверка и границы

`tests/m3g.test.mjs` проверяет хеш модуля, создание настоящего RGB565-буфера, зелёный native clear, загрузку неизменённого `gnex.m3g`, реальные дочерние объекты World и побитовое преобразование float-массивов. Интеграционный тест запускает неизменённый Independence SGS, выполняет START и пять TIMEOUT и проверяет реальную цепочку load → animate → renderWorld и непустую геометрию кадра. Проверяется также нативный цикл uninitialize/initialize и идемпотентный close: ссылки на отдельный CPU, helper-замыкания и таблицы удаляются, позволяя сборщику мусора освободить память WASM. Пять тестов занимают около трёх секунд на использованной системе.

Длительный прогон прошёл анимированный логотип Swerve/GNEX, загрузку основной городской сцены, главное меню, подтверждение новой игры, инструктаж и активную миссию с HUD. Свежий прогон после исправления отпускания клавиши выполнил 106 событий без ошибки. При визуальной проверке начального кадра миссии запас ракет равнялся 4, а показатель тяги — 180; после ввода — 3 и 432. Игровые PNG не включены в публичный репозиторий; хеши кадров и сценарий сохранены в отчёте ниже, изображения можно получить повторным прогоном. Исходный сценарий продолжает вызывать animate, renderWorld, преобразования координат и проверки пересечений.

[swerve-gameplay.json](../validation/swerve-gameplay.json) содержит точные действия, полный режим виртуального времени, диагностические счётчики, хеши кадров и трассу. Прогон повторяется командой:

```sh
node tools/replay-sgs.mjs gnex26_independence_day_3d validation/independence-actions.json validation/swerve-replay
```

Ускоренное исполнение сначала исчерпывало лимит при втором `swv_loader_load`, на загрузке города. Блочный watchdog списывает две единицы за 32-битную ARM-инструкцию, поскольку считает работу по половинам слова. Загрузчик сцен получил лимит 200 млн таких единиц. Для обычных вызовов установлен лимит 100 млн единиц. Точный режим отсчитывает до 100 млн гостевых инструкций.

После исправления ускоренный и точный прогоны совпали по всей трассе из 106 событий, диагностике и всем 30 контрольным PNG. [Хеши контрольных кадров](../validation/swerve-city-load.json). В интеграционном тесте оригинальная игра загружает заставку, затем город и возвращает корректный указатель на корень второй сцены.

Здесь вступление ускорено **явными ручными шагами виртуального времени** 10 000 и 5 000 мс с одним вызовом каждого активного таймера на шаг. Это не запись обычной частоты TimerScheduler; режим явно отмечен в JSON и не меняет SGS-байткод. Отдельная проверка большой сцены получила исходный кадр с Землёй и площадкой. Эти проверки подтверждают исполнение исходной графики и управление в миссии; они не заменяют прохождения всех уровней.

До оптимизации 5 ноября 2026 года загрузка исследованной большой сцены занимала около 18 секунд, повторный самостоятельный renderWorld — около 0,77 секунды. Теперь Swerve использует ограничение работы по блокам ARM вместо дорогого счётчика каждой инструкции; GNEX VM для SGS v36 сохраняет прежнее течение телефонного времени. [Новые измерения и проверки](web-performance.md) относятся к отдельно описанному сценарию и не заменяют этот исторический замер большой сцены. Создание графа через GNEX добавляет время; браузер, нагрузка и сцена меняют результат. Аппаратного WebGL-рендеринга нет. Полная реализация всех функций исторического Swerve SDK не заявляется: покрытие определяется оригинальными вызовами этой игры и проверяется остановкой на неизвестной функции.
