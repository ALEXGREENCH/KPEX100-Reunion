# Восстановление вложений старых корейских форумов

Этот проход идёт по спискам разделов, публичным темам и прямым вложениям,
включая сохранённые CGI-ссылки без узнаваемого имени файла. Поиск по названию
дополняет обход, но не заменяет получение байтов.

Из GVM Club восстановлены **13 оригинальных вложений, 451 009 байт**.
У всех 13 SHA-1 совпал с ранее сохранённой записью CDX; дополнительно
сохранены SHA-256, исходный URL, дата снимка и HTTP Content-Disposition.
Три ALZ распакованы с проверкой длины, конца DEFLATE и CRC всех **12 файлов**.
Старые EXE, Office-макросы и сетевые серверы не запускались.
[Полные данные и результаты](../validation/gvm-forum-attachment-evidence.json).

## Файтинг zola: исходник и настоящий SGS

В [вложении 느시.alz, снимок 23 января 2004 года][zola]
находятся четыре файла: `zola.mc`, `0000102FFFFFFFF.sgs`, `down.wmls`
и `link.wml`. WML содержит буквальную подпись **졸라피이터**.
Внутреннее имя SGS пустое; название по имени исходника не следует принимать
за доказанное коммерческое название игры.

| Поле                                 | Значение                                                           |
| ------------------------------------ | ------------------------------------------------------------------ |
| Формат                               | SGS v2, без оболочки и XOR                                         |
| Размер                               | 9 354 байта                                                        |
| SHA-256                              | `0cb4c5ecfeba32aae3055fcffc8f7dd32b0ddc13da18e221585fa53916d348fc` |
| Переменные / ресурсы                 | 74 / 13                                                            |
| START / TIMEOUT / KEYPRESS / RECEIVE | `0x64` / `0x80` / `0x13ec` / `0x818`                               |
| Исходник                             | Mobile C, 17 254 байта                                             |

Исходник показывает два режима: одиночный и PTP. В `main` он сохраняет
`swData` в `GameType`. Оригинальный `SScript.h` SDK определяет
`S_GTYPE_ALONE = 1`, `S_GTYPE_PTP = 2`. Поэтому исследовательский запуск
передаёт **START data 1** через обычный интерфейс событий. Байткод и
интерпретатор не изменялись. При стандартном нуле игра остаётся на
«Are You Ready?» даже после нажатия OK.

Оригинальный Kingston ROM в Reunion исполнил одиночный бой со стикменами.
На выбранном для исследования экране 128×128 проверены движение и атаки.
Контрольный запуск нажимает только OK; запуск с управлением имеет те же
виртуальные сроки кадров. До движения кадры совпадают, после него отличаются
99 пикселей на 600 мс; после последующих действий — 152 на 900 мс и
113 на 1 500 мс. Все три запуска START 1 завершились в `idle` без ошибки.
Это короткая проверка, а не прохождение игры. PTP, звук, сохранения и
работа на настоящем телефоне не проверены; исторические серверы не вызывались.

128×128 выбран по координатам исходника, а не по установленной модели
телефона. Исходник включает отсутствующий в архиве `caracter.sbm`;
ресурсы уже находятся внутри оригинального SGS. Перекомпиляция не проверялась.
SGS пока сохранён как исследовательская находка: обычный каталог остаётся
из 55 приложений, поскольку его запуск ещё не задаёт отдельный START data
для этой игры. Исследовательский replay-скрипт и кадры включены в архив находок.

## Две презентации Sinjisoft

[LcdSound변경관련컨텐츠개발고려사항.ppt][lcd] объясняет переход к
битовым маскам аудиовозможностей. Значение MA3 — `0x20`, а описанный
телефон с MA2 и MA3 возвращает `0x24`. Проверять такую возможность нужно
битовой операцией, а не равенством одному значению. Это историческое
описание GetHwConfig, не основание приписывать MA3 всем профилям Reunion.

Там же перечислены исключения из новой классификации LCD: Prime800/TP226,
CX-300A, X-230 и X-250 сохраняют старый LCD Class 1. В одном абзаце
про LCD оригинал пишет `AUDIOTYPE`; этот текст сохранён, его нельзя
молча превращать в точное правило заголовка. Дата 2001.6.8 находится
в мастер-элементах и не устанавливает дату публикации презентации.

[011120\_비압축GVM컨텐츠개발가이드.ppt][compression] описывает выбор
сжатого/несжатого контента через IMAGETYPE и приводит пары примеров
с 4 и 12. Документ рекомендует несжатый вариант для сокращения времени
подготовки приложения. В тексте есть опечатка `IMAGETEYPE`, тогда как
образцы кода используют `IMAGETYPE`. Это не изменение декодера Reunion
и не новый восстановленный алгоритм сжатия.

Из OLE извлечены оригинальные потоки PowerPoint Document; разобраны
951 и 395 записей, включая 74 и 17 текстовых атомов. Исходные презентации
сохранены без конвертации; полный текст и смещения находятся в evidence.

## Таблицы устройств

[GVM_phone.xls][phones] содержит лист Sheet3 и внутреннюю дату
**2002.12.18**: 108 строк моделей с полями производителя, LCD,
области GVM, идентификатора, версии и статуса выпуска. Среди строк есть
`출시예정` — планируемый выпуск. Это не 108 новых подтверждённых
серийных телефонов и не дополнение арифметикой к прежним перечням.

[단말기별*마법사*컨텐츠*이용률*현황.xls][usage] содержит 75 строк моделей,
области GVM и статистические доли. Исходные пустые ячейки группировок
сохранены. Срок снимка Wayback не подменяет дату сбора статистики.
Указанные в таблицах размеры могут отличаться от более поздних версий;
они не переписывают профили эмулятора автоматически.

Сравнение с уже восстановленными справочниками дало важные уточнения:

- Декабрьская **планируемая** `SV-120(SHX2F)` имеет LG3511.
  В таблице оператора 2003 года LG35 относится к **SV9120(SHX2F)**,
  а отдельная SV120(SHX2V) имеет LG43. Эти названия нельзя объединять.
- Для SD-100(S415) декабрьский лист явно называет GVM **128×112**;
  ноябрьский PDF указывает 128×128. Оба значения сохранены с датами источников.
- В статистическом листе появились буквальные варианты **X127SS / X137SS**;
  это новые зафиксированные написания, без доказательства отдельного железа.
- Версии CYBER-VX2, CYBER-6000 и X150 между листами расходятся.
  Статистика ссылается на CP meeting 2002 года без доказанного месяца;
  выводить последовательность обновлений из этих различий нельзя.

Алиасы D510/D610V/D400 уже были в ноябрьском PDF. Разные EE-коды
в декабрьской сноске обозначают формы поставки/оператора, а не автоматически
ещё несколько устройств. [Сравнение и исходные строки](../validation/korean-naver-source-evidence.json).

## Остальные исходники и данные

- [2.alz][hello] содержит шесть файлов примера Hello/Smile/Sound.
  Отдельный [2.mc][hello-mc] выводит HelloWorld на GVM1X.
- [SSRS232C_Simple.mc][serial] — тест RsCom/RsSend и EVENT_RSRECEIVE.
  В нём остаются исходные спорные индексы и способ печати hex; это
  исторический пример, не готовая утилита чтения файлов телефона.
- [wml.alz][wml] содержит только два файла WAP-меню/загрузки, без SGS.
- [echo.mc][echo] — сетевой ECHO TEST/клиент меню;
  [NetConnect.txt][net] — фрагмент автомата подключения.
  Доступность старых сервисов не проверялась.
- [a.c][nv] — пример чтения и записи пользовательского NV.
- [holysd.H][holysd] содержит три таблицы: holysdObj — 18 441,
  holysdTex1 — 8 192, holysdMot — 4 097 целых элементов.
  Все количества проверены. Реализации 3D-движка и полного проекта здесь нет.

Эти оригинальные сторонние материалы сохраняют своё происхождение;
лицензия Reunion не перелицензирует их. Связанные исследования:
[ранние руководства GVM Club](gvm-early-service-guides.md),
[WI-TOP и Hellfire](gvm-community-recovery.md),
[таблицы телефонов 2002–2003 годов](gvm-historical-handsets.md).

## Публичные вложения Naver: BomberMan и NMTool

Обход реальных меню четырёх клубов дал десять страниц списков и 146 строк
тем. Из десяти открытых тем без входа получены десять ZIP; семь относятся
к GVM/инструментам, три других — отдельные WIPI native-пакеты.
[URL, флаги публичного чтения, хеши и состав](../validation/korean-naver-source-evidence.json).

[Jinimobile, тема 22 от 16 июля 2004 года](https://cafe.naver.com/jinimobile/22)
содержит `2004_BomberMan3.zip`: **1 619 722 байта**, SHA-256
`da6d2012d95d7abe38e1a097fd22989e8b260dfc9ad1b8decdb539ed30539346`.
Все 57 файлов прошли ZIP CRC. Внутри два варианта клиента BomberMan
на Mobile C, Flow Control и No Flow Control, ресурсы изображения/звука,
Linux C-сервер, makefiles, SQL и проектные документы. Исходники клиента
содержат SINJISOFT/copyright 2003, SCRIPTVER 1 и SCRIPTTYPE 3.
Готового SGS в архиве нет; компиляция и сетевой запуск не выполнялись.

[Jinimobile, тема 18](https://cafe.naver.com/jinimobile/18) даёт
**Neo Mobile Map Tool 1.1**, `NMTool.zip`, 1 960 991 байт, SHA-256
`a2baf3b688c2c0c0ad587255c7f2bbccbb9c9b3d2473fe1840beb595540588c3`.
Архив действительно содержит MFC C++ исходники и образцы проекта.
Пост описывает экспорт в C для GVM, атрибуты тайлов, события и зеркалирование.
Сборка не проверялась; публикация исходников не означает разрешительную лицензию.

В [теме 8](https://cafe.naver.com/jinimobile/8) сохранены документы
процедуры запуска сервиса SKT, в [теме 9](https://cafe.naver.com/jinimobile/9)
— инструкция по иконкам SKVM/GVM. Эти DOC/PPT получены целиком с проверкой
CRC, их содержимое пока не исследовано полностью.

Три темы Mobileprograming от 13 сентября 2004 года содержат учебные
исходники и оригинальный байткод:

| Тема                                             | SGS                    | Проверка в Reunion                      |
| ------------------------------------------------ | ---------------------- | --------------------------------------- |
| [34](https://cafe.naver.com/mobileprograming/34) | Hello.sgs, 140 байт    | Отрисован текст, idle без ошибки        |
| [35](https://cafe.naver.com/mobileprograming/35) | line.sgs, 134 байта    | Текущий строгий парсер отклоняет layout |
| [36](https://cafe.naver.com/mobileprograming/36) | Image.sgs, 5 902 байта | Отрисовано изображение, idle без ошибки |

Для Hello/Image выбран исследовательский экран 128×160, не установлена
точная модель телефона. У оригинального Line поля секций — 70, 134,
70, 70. Возможен вариант компилятора без ресурсов; одного отказа парсера
недостаточно, чтобы объявить оригинал повреждённым. Байты не исправлялись.
Эти примеры не увеличивают количество розничных игр каталога.

Три проверенных игровых архива EV-K100 содержат WIPI native/Clet
`client.bin*`, хотя один соседний текст описывает другую GNEX-версию игры.
Расширение контейнера `.jar` и общий игровой заголовок не заменяют анализ
исполняемого формата; эти пакеты оставлены за пределами набора GVM.

## Учебный проект Lala из JZSDN

В [публичной теме JZSDN от 10 октября 2006 года](https://cafe.naver.com/jzsdn/8970)
сохранился `lala.zip`, 1 224 627 байт, SHA-256
`2439ed27f789f4e651694412a46df1dada73d420e122c5ee19c767477223c6ae`.
Все 386 ZIP-записей прошли CRC. Вместе с Mobile C и проектом GNX
находится оригинальный **lala.sgs**, GNEX 4, 65 210 байт:
`0e5a8709be44788ae24b2557c75cbdb44749725110867b468a9a7d2a32acd747`.
Внутреннее имя — `lala GNEX App`, таблица содержит 25 переменных и три
ресурса изображения; секции покрывают файл до EOF.

Это учебное движение персонажа, не новая розничная игра. Оригинал без
изменений рисует фон и персонажа в Reunion. При одинаковом времени
300 мс стрелки вправо/вниз дают отличие в 817 пикселей от контроля без ввода;
начальные кадры совпадают. Проверочный экран 128×146 выбран исследователем:
LCDCLASS 255 не устанавливает конкретный телефон.
В исходнике есть отдельная ветка GVM2, но полученный бинарник только v4;
результат не доказывает наличие скомпилированного GVM2-варианта.
[Происхождение, разбор и replay](../validation/lala-gnex-example-evidence.json).
