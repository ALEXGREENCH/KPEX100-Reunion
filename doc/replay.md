# Воспроизведение игровых сценариев

`tools/replay-sgs.mjs` запускает оригинальный интерпретатор без окна браузера. Профиль телефона берётся из каталога; три таймера исполняются по порядку виртуальных сроков. Каждый шаг сохраняет настоящий framebuffer PNG, итоговый JSON содержит действия и диагностику. Это инструмент для воспроизведения ошибок и проверки регрессий.

```sh
node tools/replay-sgs.mjs gnex16_bubble_bubble actions.json validation/bubble
```

Для SGS, которого нет в каталоге, укажите файл и каталог результатов явно:

```sh
node tools/replay-sgs.mjs --file /path/game.sgs actions.json validation/imported-game
```

Принимаются обычные файлы SGS v1/v2/v4/v36 размером до 12 МиБ + 32 байта;
обёртка и XOR распознаются существующим парсером. Профиль телефона не угадывается:
задайте `runtime` в сценарии, иначе действуют стандартные параметры интерпретатора.
Используется тот же оригинальный Kingston 2.12 ROM; для v36 также нужен Swerve.
Имена PNG и JSON начинаются с `local-` и очищенного имени файла без `.sgs`.
В отчёт добавляются версия, размер и SHA-256 исходного SGS. Файл игры не изменяется.

Пример `actions.json`:

```json
[
  ["tick", 40],
  ["key", 20],
  ["key", 1],
  ["tick", 30],
  ["hold", 17],
  ["tick", 10],
  ["release", 17]
]
```

`tick` доставляет указанное количество срабатываний **установленных игрой** таймеров; при отсутствии активного таймера ничего не происходит. `key` нажимает и отпускает клавишу, `hold` оставляет её нажатой, `release` отпускает. Код записывается десятичным числом: 20 = OK, 16/17/18/19 = влево/вправо/вверх/вниз, 1–9 = цифры, 10 = 0, 11 = \*, 12 = #, 13 = CLR, 21/22 = F1/F2, 23 = ENTER.

`["advance", 1000]` продвигает виртуальное время на 1 000 мс и доставляет
только таймеры, срок которых наступил за этот интервал. Принимаются 0–10 000 мс;
более длинные интервалы разбиваются на несколько действий. Время сохраняется
и между сроками таймеров, а `advance` с нулём не вызывает события.
Это позволяет сравнивать ввод и бездействие при одинаковом времени.
Один шаг ограничен 10 000 событиями таймеров.

Для воспроизводимого собственного профиля JSON может иметь вид `{ "runtime": { "width": 176, "height": 220 }, "actions": [...] }`. Этот параметр задаёт окружение; байткод и ресурсы SGS остаются исходными. Идентификаторы каталога, заголовки, смещения событий и ресурсы можно посмотреть через `sgs-info.mjs`.

`runtime.startData` задаёт беззнаковое 32-битное значение события START;
по умолчанию оно равно нулю. Например, [Zola](gvm-forum-attachments.md)
нуждается в `startData: 1` для одиночного режима согласно исходному Mobile C
и `S_GTYPE_ALONE` SDK. Профиль применяется и в браузере, и в replay.
При прямом вызове `runtime.event('START', value)` явный аргумент заменяет
значение профиля; параметры остальных событий не меняются.

Прогон без ошибки означает только успешное выполнение данного сценария. Проверку загрузки, меню, действительного игрового процесса, управления и сохранения следует фиксировать отдельно. Снимок заставки не служит доказательством работоспособности игры целиком.
