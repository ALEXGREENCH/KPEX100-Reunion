# Raw MA1: разборщик SDK и регистры Yamaha

7 ноября 2026 года получен воспроизводимый эталон MA1 из сохранённого
x86-эмулятора GVM. Новый инструмент исполняет его звуковой обработчик
в изолированной памяти Unicorn и перехватывает обращения к MIDI,
таймерам и выделению памяти. Windows, драйверы и потоки не запускаются.

Проверены пять неизменённых MA1 из WI-TOP Hellfire и три синтетических
набора: **820 слов партитуры, 1 015 команд MIDI, 1 278 запросов таймеров**.
JavaScript-разборщик совпал со всеми наблюдаемыми полями этих 820 слов.
Это подготовка к воспроизведению MA1; **FM-синтез raw MA1 пока отсутствует**.
Действующий путь [зуммера GVM](gvm-buzzer-audio.md) не изменён.

## Входные данные

Исследуется `2x_Cr256_Magic.exe`, 1 056 768 байт, SHA-256
`2bcc2554605bc277a99ff1220db1a509f875c207221647f806d0fff3efd66f88`.
Он уже сохранён в [комплекте ранних SDK-страниц и GVM2X](../research/archives/GNEX-Early-SDK-Pages-and-GVM2X-Original.zip).
Происхождение и отличия двух копий описаны в
[предыдущем отчёте](gnex-early-sdk-player-followup.md).
Этот исторический EXE модифицирован; подлинность нетронутого выпуска
Sinjisoft ему не приписывается.

Пять ресурсов 45–49 взяты из SGS с SHA-256
`37a3310b683e47b90e070e8772ac3ad267be172d11799f1168a2350fe448eec8`.
Их точное соответствие массивам `Hellfire_Ma1.ssd` ранее проверено
в [исследовании зуммера и исходников](gvm-buzzer-audio.md).
Входной SGS, ресурсы, EXE и PDF не исправлялись.

## Что исполняет инструмент

[inspect-gvm-ma1.py](../tools/inspect-gvm-ma1.py) принимает только указанный
PE и пять ресурсов с точными хешами. Инициализация находится в `0x403750`,
обработчик таймеров — `0x403340`. Поля слова наблюдаются в `0x4034ea`
после штатных операций x86; таблицы интервалов и длительностей читаются
из самого PE по `0x46da90` и `0x46daa0`.

На один вызов установлен предел 200 000 инструкций; на один набор —
2 000 000 инструкций, 10 000 вызовов таймера и 180 виртуальных секунд.
Все восемь наборов выполнили суммарно 330 156 инструкций. Исходные
инструкции SDK действительно эмулируются; это не только статическое чтение.

Вызовы WinMM возвращаются из контролируемых заглушек. Таймеры выполняются
детерминированно, одинаковое время разрешается порядком регистрации.
Записаны MIDI-команды и запрошенные задержки, а не звучание Windows
или измерения физического телефона. Зарезервированные коды высоты в
синтетическом наборе характеризуют обработчик SDK; их корректность
для микросхемы этим не подтверждается.

[Полный эталон](../validation/gvm-ma1-native-reference.json) содержит
исходные payload, разобранные поля, MIDI и таймеры для каждого набора.
Интеграционная проверка отдельно связывает первые пять с оригинальным SGS.

## Разметка и обнаруженные различия

[ma1.js](../web/engine/ma1.js) читает little-endian заголовок, длину,
восемь тембров по два оператора, девять регистров и партитуру со смещения 86. Сохраняются исходные слова, признаки паузы, смены тембра и tie/slur.
Границы определяются объявленной длиной; дополнительные байты явно
учитываются как `trailingBytes`. Разборщик не изменяет входную память.

В SDK слово назначения `0x3210` даёт каналам тембры `[3, 2, 1, 0]`.
Порядок из описания регистра Yamaha — `[0, 1, 2, 3]`.
В JSON эти варианты названы отдельно: `sdkVoiceAssignments` и
`registerVoiceAssignments`. Нельзя переносить Windows-вариант в
будущий FM-рендерер без проверки.

Аналогично разделены `sdkWholeNoteMs` и `nominalWholeNoteMs`.
Для регистра темпа 14 SDK вычисляет 392 мс; формула Yamaha даёт примерно
411,946 мс. SDK дополнительно ограничивает задержки таймеров снизу
24 мс при переданном системном минимуме 1 мс и откладывает первый
вызов обработки партитуры на 100 мс. Эти задержки относятся к реализации
WinMM, а не к доказанной временной модели телефона.

Сохранённый PDF Yamaha B2 2000.4 также имеет неоднозначность: таблица пауз
на стр. 13 названа одинаковой с таблицей нот, однако для интервалов
`0` и `B` напечатаны другие значения. В эталоне SDK это нулевые интервалы.
Текущий разборщик публикует поля `sdkIntervalTicks`; неподтверждённая
поправка к длительности не вносилась.

Для параметров операторов дополнительно просмотрены полные стр. 10, 12,
13, 15 и 16 того же PDF. Он повторно включён неизменённым: 43 страницы
производителя и приложение дистрибьютора. Это ранее полученный файл,
без нового руководства или новой версии SDK.

## Использование

Для просмотра ресурсов нужен Node.js 22+ и полный checkout:

```sh
node tools/ma1-info.mjs web/data/games/hellfire-witop-v1.sgs 45
node tools/ma1-info.mjs extracted-ma1.bin
```

Команда выводит JSON и проверяет формат; звук не воспроизводится.
Для повторного независимого эталона нужны Python 3.11+ и `unicorn==2.1.4`:

```sh
python tools/inspect-gvm-ma1.py originals/2x_Cr256_Magic.exe fixtures/ma1-original-resources.json --output native-local.json
node --test tests/unit/ma1.test.mjs tests/gvm-ma1.test.mjs
```

Выходной JSON должен быть новым. Сравните его с `derived/gvm-ma1-native-reference.json`
из комплекта. Тесты проверяют нативные поля, длины, subview, padding,
повреждённые заголовки, параметры операторов, разные порядки тембров
и запуск CLI на оригинальном SGS.

## Сохранение

[Скачать комплект](../research/archives/GVM-MA1-Native-Reference-and-Register-Research.zip)
— 1 166 911 байт, SHA-256
`5dd90fce29aad084dc82247db91b4abc049fb4b99f78cf88b1617d6caa0730ee`.
[Проверка](../validation/gvm-ma1-preservation.json) подтверждает CRC 23 файлов
и SHA-256 22 записей манифеста. Внутри точные ранее сохранённые EXE и PDF,
исходные квитанции, происхождение из предыдущих ZIP, инструменты,
фикстуры, новые трассы и производные представления.

Следующий шаг — реализовать FM-голоса и последовательность по подтверждённой
модели, отдельно проверить выбор звукового устройства и отмену запросов.
Текущий MIDI-эталон SDK не заменяет этот шаг. Редкие SDK 1.20/1.40
и самостоятельный телефонный проигрыватель здесь не восстановлены.
