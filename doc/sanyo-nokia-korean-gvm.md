# Корейские Sanyo и Nokia: прошивка, GVM и встроенная Snake II

Получены три оригинальных архивных образа Sanyo/Telson и руководство
Nokia 8887. В конкретной прошивке Sanyo SCP-A011 подтверждены пути,
загрузчик и сообщения GVM. Для Nokia 8887 инструкция устанавливает
наличие встроенной Snake II и отдельно описывает скачиваемые приложения.
Новых полных SGS в этих трёх образах не восстановлено.

[Исходные адреса, SHA-256, CRC и смещения](../validation/sanyo-nokia-korean-evidence.json).

## Sanyo SCP-A011 K2 V2000

[Исходный архив](https://archive.sunderland93.ru/Firmwares/Sanyo/SCP-A011/SCP_A011_K2_V2000.7z)
занимает 3 864 848 байт. Единственный член `SCP_A011_K2_V2000.bin` —
14 614 532 байта, SHA-256:

```text
07fe2747ec2e4e9eadb4f32b79fb47d560249d13d50a228f6e0d73bccba29a80
```

В самом BIN есть модель SCP-A011, сборка V2000 и дата Feb 12 2003.
Код содержит раздельные каталоги `/skp/c/GVM/` и `/skp/c/SKVM/`,
параметры GVM-запуска с CPID/GID, расширение `.sgs`, отдельные MIME для
GVM INF/SGS и SKVM JAR. Имеются таблицы исключений интерпретатора,
включая Invalid OPcode и Wrong Compressed Script.

| Байты в образе   | Смещение   |
| ---------------- | ---------- |
| `SCP-A011`       | `0x1808`   |
| `V2000`          | `0x3df1b8` |
| `/skp/c/GVM/`    | `0x31056a` |
| `mmiInitEnv()`   | `0x4c4691` |
| `.sgs`           | `0x4c4778` |
| `Invalid OPcode` | `0x4e2051` |
| `GVM Error!`     | `0x4e2c68` |

Историческая [таблица SKT/STI](gvm-historical-handsets.md), строка 230
листа SKT, независимо указывает SCP-A011, поддержку GVM 2 и SKVM 1,
физический экран 132×176 и область приложений 132×160.
Текст GVM1X в сообщениях ROM не используется для вывода, что эта сборка
поддерживает только одну старую VM. Версия среды из XLS и присутствие
реализации в конкретном образе остаются отдельными свидетельствами.

Размер файла — `0xdf0004`. Последние четыре байта `f2 43 58 f5`
совпадают с little-endian CRC32 предыдущих `0xdf0000` байт, `f55843f2`.
CRC32 всего файла — `2144df1c`, он же указан в 7z. Это проверка
целостности данного файла; она не устанавливает его заводскую подлинность
и не доказывает, что файл охватывает всю память телефона.

## Нативный интерпретатор SCP-A011

Статический разбор исходного Thumb-кода устанавливает настоящий
интерпретатор, который читает 8-битные операции и вызывает обработчики
через таблицу указателей. Все адреса ниже — смещения в BIN; физические
адреса исполнения и база состояния SB/R9 не установлены.

| Участок                            | Смещение в BIN        |
| ---------------------------------- | --------------------- |
| Инициализация таблицы обработчиков | `0x4d6640`–`0x4d6ea8` |
| Загрузчик старого заголовка SGS    | `0x4d6ff0`            |
| Исполнитель события                | `0x4d72dc`            |
| Чтение байта операции              | `0x4d72fc`            |
| Косвенный вызов обработчика        | `0x4d730e`            |

Из 758 инструкций инициализации восстановлены 240 однозначных записей
для операций `0x00`–`0xef`; каждая указывает на Thumb-код исходного файла.
Проверка в исполнителе допускает также `0xf0`, но данная инициализация
эту запись не заполняет. Её окончательное значение остаётся неизвестным.
Байт `0xff` завершает событие.

Загрузчик читает little-endian 16-битные смещения разделов по +44/+46/+48/+50.
Обёртка START читает точку входа из +28/+29. Это согласуется со старым SGS,
включая разобранный [образец Hellfire](gvm-community-recovery.md), однако
на оригинальном интерпретаторе Sanyo этот образец не запускался.

[Исходные байты, поля состояния и границы выводов](../validation/sanyo-a011-vm-evidence.json),
[полная таблица и след вычислений](../validation/sanyo-a011-dispatch.json).
Например, обработчик `0xba` в Sanyo извлекает одно 16-битное значение со
стека и сохраняет его младший байт в состоянии VM. Позднее статический
разбор оригинального ассемблера SDK подтвердил имя **LockChatMode**;
`0xbb` соответствует SetChatMode, `0xc4` — BackToBrowser.
[Таблицы и путь записи байта операции](gnex-sdk-internal-sources.md#legacy-команды-0xba-0xbb-и-0xc4).
Это уточняет имена, но не переносит телефонные callback и интерфейс чата
в Kingston автоматически. Пропускать операции как NOP оснований нет.

[Переносимый инструмент](../tools/inspect-sanyo-a011-vm.py) повторяет
вычисление таблицы без исполнения прошивки. Он принимает только точный
BIN указанного размера/SHA-256 и создаёт новый JSON без перезаписи.
Для побайтного повторения следа использован Python 3.11 и Capstone 5.0.7:

```sh
python -m pip install capstone==5.0.7
python tools/inspect-sanyo-a011-vm.py /path/to/SCP_A011_K2_V2000.bin /path/to/new-dispatch.json
```

Это инструмент статического анализа конкретной сборки. Эмуляция полной
прошивки Sanyo и перенос её операций в Kingston остаются отдельной работой.

## Nokia 8887: встроенная игра и NATE

[Оригинальное руководство, сохранённое зеркалом](https://altehandys.de/downloads/man-no-8887.pdf)
содержит 63 PDF-страницы, 2 697 696 байт, SHA-256:

```text
c7851330e0a06905290b5d9cbf016b6140ca15893992be934228a7399861b446
```

На первой странице явно указана Nokia 8887. PDF-страницы 45–46,
печатные 39–40, называют **Snake II** встроенной игрой меню Game / Menu 6.
Описаны продолжение игры, новая игра и выбор сложности. PDF-страница 35,
печатная 29, отдельно описывает NATE wizard и Wizard archive: загруженные
игры и музыка сохраняются в телефоне и доступны вне соединения.

Справочник Sinjisoft на страницах 81–82 включает региональные
**TDC-8887 и TDC-8587** в раздел Nokia, GVM2X / SCRIPTVER 2 / Magic.
Эти сведения не устанавливают SGS-формат встроенной Snake II.
Её игровой файл и прошивка именно этих Nokia ещё не получены.

В полученном корневом каталоге прошивок Sunderland Nokia нет папок с
именами 8887/8587. В каталоге Telson имеется только PS3000. Это результаты
проверки конкретных списков; другие архивы, внутренние обозначения и
оставшиеся копии не исключаются. Родство PS3000 с Nokia не предполагается.

Все три архива прошли 7z CRC, размеры и CRC32 членов сверены с таблицами
архивов. Сканер проверил 17 760 244 байта, SGS v1/v2/v4/v36 в открытом
виде и с XOR A5: структурно валидных непрерывных контейнеров не найдено.
Дополнительно выполнен узкий поиск известных LG-подобных страниц на
границах 512/1024 байта; технических имён SGS/INF/GVM/RES не найдено.
Этот поиск не является универсальным разбором файловой системы.

Сжатые, фрагментированные, иначе упакованные и native-игры не исключены.
Полный запуск этих прошивок в Reunion не проверялся; старые программы
не запускались, пользовательские записи из памяти не экспортировались.
