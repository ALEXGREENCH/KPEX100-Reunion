# Зуммер GVM и исследование MA1

Ранний звуковой подтип **0** теперь воспроизводится в телефонном профиле.
В WI-TOP Hellfire работают монофоническая тема и эффекты из исходных ресурсов.
Байты SGS, ROM и звуковых таблиц в игре не менялись. Подтип **1**, raw MA1,
остаётся отдельной задачей: он не заменяется зуммером.

[Скачать комплект](../research/archives/GVM-Buzzer-and-MA1-Source-Research.zip)
— 879 755 байт, SHA-256
`20e14fd05e26d53bb4b2f7d8834608ca4a818380b604b218aeea66078c86a601`.
[Проверка архива и происхождения](../validation/gvm-buzzer-preservation.json):
CRC 28 файлов, SHA-256 27 записей манифеста совпали.
[Результаты воспроизведения и уровней громкости](../validation/gvm-buzzer-playback.json).

## Эталон SDK

Полученный `2x_Cr256_Magic.exe`, 1 056 768 байт, SHA-256
`2bcc2554605bc277a99ff1220db1a509f875c207221647f806d0fff3efd66f88`,
содержит обработчик зуммера по VA `0x401030..0x4010f7`.
Его таблица 37 частот находится по `0x48c16c`.

После двухбайтного типа идут пары «номер ноты, длительность»:

| Номер     | Поведение                                                 |
| --------- | --------------------------------------------------------- |
| 0–36      | Частота из таблицы SDK, длительность — второй байт × 3 мс |
| 37        | Пауза такой же длительности                               |
| 38 и выше | Конец воспроизведения                                     |

Нулевые длительности сохраняются. Конечный маркер не требует чтения
следующего байта. При обрезанной паре или отсутствии маркера декодер
сообщает ошибку вместо чтения за пределами ресурса.

Таблица используется буквально: например, в ней есть 923 Гц.
Она не заменяется расчётом частот по названиям нот. Это поведение
конкретного Windows SDK; совпадение с динамиком каждого телефона не доказано.

[Независимый эталон](../validation/gvm-buzzer-native-reference.json)
получен [инструментом](../tools/inspect-gvm-buzzer.py) через изолированное
исполнение проверенных инструкций x86. Вызовы Beep, ожидания и остановки
перехвачены как записи событий; Windows, устройство и портовый ввод-вывод
не запускаются. Есть предел исполнения и фиксированный хеш исходника.
Это проверка порядка, частот и длительностей, без проверки физического тембра.

Восемь векторов, 209 событий охватывают пять исходных ресурсов Hellfire,
все 37 нот и паузу с длительностями 0/1/255, пустой поток и высокий
конечный байт. SGS v1/v2 и произвольные другие аудиоподтипы не смешиваются.

## Путь воспроизведения

VM отправляет неизменённый ресурс как `audio/x-gvm-buzzer`.
Отдельный аудио-Worker создаёт ограниченный моно PCM WAVE; обработчик
инструкций ARM и основной поток страницы не синтезируют сэмплы.
Существующий Web Audio применяет паузу, громкость канала и пользовательский
уровень. Сохраняются канал, флаг повтора и отмена предыдущего запроса.
Ключ кеша включает формат и SHA-256: одинаковые входные байты разных
форматов не могут получить чужой PCM.

Выход — прямоугольная волна с амплитудой около 0,2. Это приближение
динамика SDK; аналоговый тракт телефона и его АЧХ не моделируются.
Суммарные границы нот считаются по времени, без накопления ошибки
округления на каждой паре. Ограничение — три минуты на запрос;
длинный результат помечается усечённым. Во время генерации можно отменить
запрос. Пустой поток останавливает предыдущее воспроизведение.

Режим K-PEX сохраняет прежнюю маршрутизацию подтипов. Поддержка SMAF,
MP3 и WAVE остаётся в существующем тракте.

Пять начальных массивов `Hellfire_Bzr.ssd` и пять из `Hellfire_Ma1.ssd`
побайтово совпали с ресурсами 40–49 WI-TOP SGS. Извлечения SDK сверены
с ранее опубликованными членами архивов. Это соответствие звуковых массивов,
а не доказательство идентичности всей сборки Hellfire.

## MA1 и сохранённое руководство

Сохранён полученный PDF **Yamaha YMU757B / MA-1C, LSI-4MU757B2, 2000.4**:
703 749 байт, SHA-256
`2af21285ed813eaed4b056b97ce9d4b8e09c133bf2c40d9bbb4a2fa8b115c623`.
[Страница источника](https://www.datasheetarchive.com/datasheet/YMU757B/Yamaha?term=YMU757B).
Файл зеркала содержит 43 страницы производителя и добавленный лист
дистрибьютора — всего 44. Он сохранён целиком без удаления приложения.

Прочитаны текст и размеры всех страниц; визуально проверены 1, 9, 11,
14, 17 и 44. MuPDF сообщил ошибку цветового профиля; выбранные страницы
отрендерились разборчиво. Это не визуальная проверка всего документа.

Другой результат поиска показывал редакцию B3 2004.4. Прямой запрос
Вашингтонского университета вернул HTML выбора провайдера входа.
Этот ответ записан как неудачное получение PDF. Редакции не объединялись,
вход в аккаунт не выполнялся.

В пяти raw MA1 проверены длина, восемь восьмибайтных тембров, блок
регистров и смещение последовательности `86`. Разметка сопоставлена
с обработчиком SDK и картой регистров Yamaha. Полный FM-синтез этих
потоков и их точная временная модель ещё не реализованы.

## Повтор проверки

```sh
node --test tests/unit/buzzer.test.mjs tests/gvm-buzzer.test.mjs
```

Для воспроизведения x86-эталона нужны `capstone==5.0.9`, `unicorn==2.1.4`
и исходный PE с указанным хешем:

```sh
python tools/inspect-gvm-buzzer.py 2x_Cr256_Magic.exe buzzer-original-resources.json --output native-buzzer.json
```

Файл входных ресурсов находится в `derived` исследовательского ZIP.
Тест отдельно связывает его с неизменённым SGS из каталога.
Программные проверки охватывают PCM, измеренную частоту и тишину пауз,
границы памяти и длительности, отмену, разделение кеша, маршрут оригинального
SGS и сохранение старого поведения K-PEX. Реальный Chrome также декодировал
и запустил буферы; измерительный узел Web Audio зафиксировал ненулевой сигнал.
Это не прослушивание физического телефона.

Архив с оригинальным PDF, страницами источников, исходными извлечениями SDK,
разбором MA1 и производным WAVE опубликован в исследовательском каталоге.
Права на исторические материалы сохраняются за их авторами.

[Разбор raw MA1 и нативный эталон](gvm-ma1-native-reference.md): 820 слов,
перехваченные MIDI/таймеры SDK и отдельное представление регистров Yamaha.
FM-синтез raw MA1 пока не реализован.
