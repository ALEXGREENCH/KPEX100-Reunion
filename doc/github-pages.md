# Публикация на GitHub Pages

[Публичная сборка Reunion](https://alexgreench.github.io/KPEX100-Reunion/)
публикуется из [ALEXGREENCH/KPEX100-Reunion](https://github.com/ALEXGREENCH/KPEX100-Reunion).
Инструкция ниже позволяет развернуть собственную копию, включая fork.

Веб-версия — статический сайт с Web Worker и WebAssembly. Она не требует
серверной базы данных или Node.js на хостинге. Node.js нужен для локальных
проверок и подготовки каталога `site/`.

## Подготовить репозиторий

1. Создайте свой репозиторий GitHub и загрузите в него исходники с веткой `main`.
2. Убедитесь, что в коммит попали `.github/workflows/`, `web/`, `tools/`,
   `vendor/`, файлы npm и вся включённая коллекция ROM/SGS, состояний и Swerve.
   Сборка проверит размеры и хеши всего набора из 78 исторических файлов.
3. В **Settings → Pages → Build and deployment → Source** выберите
   **GitHub Actions**.
4. Откройте вкладку **Actions** и запустите workflow Pages либо сделайте push
   в `main`. При первом использовании Actions в fork может понадобиться
   включить workflows в интерфейсе GitHub.
5. После успешного deploy откройте URL из окружения `github-pages`.

Обычный адрес project Pages — `https://OWNER.github.io/REPOSITORY/`.
Имя репозитория не зашито в приложение: относительные пути загружают скрипты,
Worker, WASM и каталог внутри текущего префикса. Этот же набор файлов можно
разместить в корне собственного статического сайта.

Workflow использует официальные действия GitHub для настройки Pages,
загрузки статического артефакта и deployment. Для публикации ему нужны
`pages: write` и `id-token: write`; доступ к исходникам остаётся `contents: read`.
Основание и актуальные настройки: [официальная инструкция GitHub](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Проверить локально

```sh
npm ci
npm test
npm run build
npm run preview
```

`site/` создаётся из исходников `web/`. Готовые WASM-библиотеки уже включены;
Emscripten для обычной сборки сайта не нужен. Предпросмотр обслуживает именно
подготовленный сайт. Не открывайте `site/index.html` через `file://`.

Чтобы проверить именно адрес с именем репозитория, запустите предпросмотр
с префиксом (при необходимости на другом порту):

```sh
npm run preview -- --base /KPEX100-Reunion/ --port 5180
```

Откройте `http://127.0.0.1:5180/KPEX100-Reunion/`. Команда `npm run check:site`
дополнительно проверяет статическую сборку и её ресурсы; полный набор обычных
проверок объединён в `npm run check`.

Обычная сборка включает 9 ROM, 68 SGS, 3 быстрых состояния и
модуль `swv21brew.mod`. Посетитель выбирает игру в библиотеке; дополнительный
импорт для включённых приложений не требуется. Если файл отсутствует или его
SHA-256 отличается, полная сборка останавливается с диагностикой.

При необходимости подготовить отдельный сайт без коллекции используйте:

```sh
npm run build:source-only
npm run preview
```

В этой необязательной сборке посетитель добавляет файлы через браузер. Для SGS
нужны Kingston 2.12 и выбранная игра; для Independence Day 3D — также Swerve.
Workflow Pages использует полную сборку `npm run build`.

## Что хранится у посетителя

Включённые файлы загружаются с Pages как обычные статические ресурсы.
Дополнительные файлы, выбранные посетителем, обрабатываются браузером;
загрузки этих файлов на сервер GitHub Pages нет. Сохранения используют IndexedDB
данного origin. Адрес
локального сервера, адрес GitHub Pages и собственный домен — разные origin;
сохранения между ними автоматически не переносятся. Используйте экспорт и
импорт сохранений в интерфейсе. Очистка данных сайта удаляет локальное хранилище.

## Если сайт не открылся

Страница `research/` публикует каталог исследовательских архивов. Сами ZIP
хранятся в `research/archives/` репозитория; ссылки скачивают точные байты через
raw.githubusercontent.com. Полная сборка проверяет их размеры и SHA-256.
В `site/` архивы не копируются; сборка `--source-only` тоже сохраняет ссылки
на публичные материалы. При переносе проекта обновите `repository` и `revision`
в `web/research/catalog.json`, если хотите раздавать архивы из своего форка.

Каталог GAME виртуального FAT16-диска растёт цепочкой кластеров: коллекция
из 68 SGS помещается целиком. Диск с исходными четырьмя играми сохраняет
прежний проверенный SHA-256.

| Симптом                           | Что проверить                                                                                                                                     |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| Deployment не создан              | Pages Source должен быть GitHub Actions; workflow включён; push выполнен в `main` или запущен вручную                                             |
| Главная страница даёт 404         | Используйте точный URL из deployment, включая `/REPOSITORY/` и завершающий `/`                                                                    |
| Скрипт или WASM даёт 404          | Публикуйте содержимое `site/`, сохраняя структуру каталогов; проверьте Network в инструментах браузера                                            |
| Каталог есть, игра не запускается | Для полной сборки проверьте загрузку файлов в Network и отчёт сборки; для `build:source-only` добавьте Kingston 2.12 и выбранную SGS через импорт |
| Нет звука                         | Нажмите запуск или кнопку звука: Web Audio требует действия пользователя                                                                          |
| 3D работает медленно              | Это текущая скорость программного ARM-рендеринга; смотрите [ограничения Swerve](swerve.md)                                                        |

Состояние публичной сборки доступно во вкладке
[Actions](https://github.com/ALEXGREENCH/KPEX100-Reunion/actions/workflows/pages.yml).
URL и журнал каждого развёртывания находятся в окружении `github-pages`.

Workflow даёт этапу Pages до 30 минут ожидания ответа сервиса (общий лимит
задания — 35 минут). 6 ноября 2026 года готовая сборка оставалась в
`updating_pages` до стандартного 10-минутного тайм-аута `deploy-pages`,
после чего действие отменило deployment. Сборка и все шесть заданий Checks
при этом прошли. При такой ситуации смотрите отдельно журнал публикации
и фактические HTTP-хеши: зелёная сборка ещё не подтверждает обновление сайта.
[Параметр timeout исходного действия GitHub](https://raw.githubusercontent.com/actions/deploy-pages/v4/action.yml)
задаётся в миллисекундах.
