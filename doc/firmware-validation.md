# Полная прошивка: скорость и проверки

Обновление от 5 ноября 2026 года касается запуска оригинальной ARM-прошивки
целиком, включая виртуальный накопитель и аппаратный ввод. Для прямого запуска
SGS действуют [отдельные измерения](web-performance.md).

## Контрольные прогоны

Все девять ROM из каталога запущены с холодного сброса и виртуальным FAT16 с
38 SGS. На отметке **100 млн виртуальных инструкций** все девять образов
выводили кадры и продолжали исполнение. Для каждого ROM с предыдущей версией
совпали регистры ARM, счётчики IRQ и LCD, состояние таймеров, хвост ATA-трассы,
SHA-256 кадра и SHA-256 всей 16 МиБ SDRAM.
[Машинный отчёт](../validation/firmware-cold-boot.json).

Два сохранённых сценария Kingston 2.12 — меню и HellFire с удержанием кнопки —
сверяются с прежними нативными эталонами после 10 млн инструкций. Отдельные
тесты исполняют гостевые инструкции для проверки записи в счётчики таймера,
маски IRQ и заменённой инструкции в SDRAM. Тест ATA проверяет, что IDENTIFY
отменяет начатую запись, а завершённая запись не меняет исходный диск сброса.

## Что ускорилось

| Kingston 2.12                                 | До, мс | После, мс | Ускорение |
| --------------------------------------------- | -----: | --------: | --------: |
| Холодный старт, первые 100 млн инструкций     |  6 321 |     5 272 |     1,20× |
| Меню, 50 млн инструкций                       |  1 071 |       826 |     1,30× |
| HellFire в полной прошивке, 20 млн инструкций |    419 |       324 |     1,29× |

В каждой паре совпало контрольное состояние.
[Сырые замеры и хеши](../validation/firmware-performance.json).

Веб-ядро читает ARM-слова напрямую из актуальной памяти Unicorn. Оба окна SDRAM
видят одни и те же байты, поэтому старое кэшированное ARM-слово не влияет на
обработку CP14/CP15. Быстрый цикл Kingston сверяет текущие инструкции перед
сокращением. Во время этого цикла модель по-прежнему обслуживает таймеры и
IRQ в прежних точках; она переносит запись счётчиков в память Unicorn до
выхода из цикла, когда их снова сможет прочитать прошивка.

Веб-Worker загружает ROM и содержимое диска параллельно, передаёт уже собранный
диск ядру без промежуточной копии и не пересылает статичный кадр. Он получает
подробный снимок CPU для панели диагностики по её расписанию, а не после
каждой порции инструкций. Минимальная длительность короткого нажатия завершается
точно на заданной виртуальной границе. Пауза сбрасывает удерживаемые кнопки.

В настольной версии размер порции подстраивается под время исполнения; поток
прошивки проверяет команды между порциями и не выжидает искусственную паузу.
Перевод RGB565 использует нативные операции Pillow с таблицей, сохраняющей
прежние значения всех цветов.

На рабочем цикле desktop без окна Tk три парных прогона по 10 млн инструкций
дали медиану **3,60 → 1,82 с** для меню и **4,05 → 1,85 с** для HellFire.
Кадры, регистры, таймеры и IRQ совпали. Порция ограничена 100 тыс. инструкций;
её длительность зависит от сцены, поэтому целевые 20 мс не гарантированы.
[Результаты прогонов](../validation/desktop-firmware-worker.json).

## Как повторить

Из корня проекта с Node.js 22 или новее:

```sh
git worktree add --detach ../reunion-reference 67382c6
node tools/benchmark-firmware.mjs ../reunion-reference
node tools/benchmark-firmware.mjs ../reunion-reference all-roms
npm run test:integration
```

Замер выполняет три чередующихся пары прогонов: первые 100 млн инструкций
Kingston 2.12, 50 млн из сохранённого меню и 20 млн из HellFire. В измерение
входит исполнение ARM и аппаратной модели, без скачивания, сборки диска,
распаковки состояния и хеширования. Скрипт сверяет конечные состояния и
выводит отдельные времена, медианное ускорение и список различающихся полей.
Массовый прогон проверяет девять ROM в одинаковых условиях.

Вывод кадров на контрольной отметке не проверяет каждый пункт меню и всю
периферию каждой модели. Аудиотракт полной прошивки, RTC, SD и USB остаются
частичными; ограничения описаны в [аппаратной модели](hardware.md).
