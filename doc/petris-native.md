# Petris через Kingston 2.12

Лаунчер SGS исполняет неизменённый Game Gear ROM Petris 1.1 beta. Для проверки файлового пути и управления он запускается из меню оригинальной Kingston 2.12 на эмулируемом ARM. Код меню, FAT16, чтение картриджа и GNEX-диспетчер выполняет сама прошивка. [Картридж, лицензия и исходники](../demos/gg/petris/README.md)

Из корня репозитория:

```sh
node tools/replay-petris-native.mjs --output /path/to/empty-directory
```

Нужны Node.js 22 или новее и оригинальные файлы полной сборки Reunion. SDK для воспроизведения не требуется. Каталог результатов должен быть пустым: инструмент не заменяет существующие файлы. Другой собранный лаунчер можно передать через `--sgs /path/to/PETRIS.SGS`.

Для проверки коротких импульсов есть `--pulse-ms 80`: длительность задаётся по модели тактирования ARM, с шагом исполнения 100 тысяч инструкций. Допустимы целые значения от 40 до 120 мс. После каждого импульса инструмент требует новое событие нажатия в штатном SGS-диспетчере; отсутствие события завершает проверку с ошибкой. Без этого параметра сохраняется прежний сценарий удержания на два или три гостевых кадра. В JSON записываются выбранный режим и фактические моменты ввода. Это проверка доставки ввода на модели, а не измерение задержки настоящей клавиатуры.

Проверка проходит заставку, два подтверждения, появление поля, движение вправо, поворот и нажатие вниз. Она сохраняет восемь кадров LCD в RGBA размером 220 × 176 и файл `native-petris.json`. В JSON находятся SHA‑256 прошивки, SGS и картриджа, операции открытия/чтения/закрытия, события `KEYPRESS`, моменты нажатия и отпускания и данные таблицы спрайтов. Прогон требует миллиардов ARM-инструкций и может занять десятки минут. Время `modeledMs` относится к модели тактирования, а не к замеру физического K-PEX.

Перед запуском проверяются исходные хеши:

| Файл            | SHA‑256                                                            |
| --------------- | ------------------------------------------------------------------ |
| Kingston 2.12   | `743d0b9a377dc6a3f0a80b7816cee575ad2f8249643876367c4bfaac54ddd19a` |
| Petris 1.1 beta | `2de507b5708cc66020a700e3f4674216cb3374fc5d39369da86221bb34a07ba9` |

Наблюдатели привязаны к этой версии прошивки. Таблица переменных GNEX находится через `0x20B405A8`; диспетчер SGS — `0x20049298`. Файловые точки входа и возврата — `0x20052374` / `0x2005DE20` для открытия, `0x20052400` / `0x2005E068` для чтения и `0x2005DE54` для закрытия. Наблюдатели записывают данные и не подменяют результаты операций. Дополнительно проверяется совпадение всех 32 КиБ картриджа в памяти после загрузки из `GAME/PETRIS.GGR`.

Успешный результат требует сдвига спрайта вправо на восемь пикселей, смены паттерна при повороте, нулевого состояния удержания после игровых нажатий и пар событий нажатия/отпускания. Положение фигуры после нажатия вниз проверяется отдельно: этот сценарий сам по себе не измеряет ускорение падения относительно нейтрального ввода. Границы шага ARM могут дать соседние гостевые кадры; сравнивать два таких прогона побайтно следует только после сопоставления фаз и последовательностей ввода.

Назначение кнопок дополнительно сверено с `src/gameplay.c` в сохранённом архиве исходников: `J_RIGHT` перемещает фигуру, фронт `J_A` вызывает поворот вправо, `J_DOWN` запрашивает более раннее падение. Это подтверждает назначение действий; численные проверки выше относятся к исполняемому ROM. [Исходник выбранной ревизии](https://github.com/bbbbbr/Petris/blob/97fa9f03f5c0fa84810da0632679481d8e0b71d1/src/gameplay.c)

Сценарий использует короткие нажатия. У оригинальной Kingston обнаружено пропадающее отпускание после автоповтора; оно воспроизводится [отдельным ARM-инструментом](hardware.md#кнопки-и-adc). Экспериментальная правка пяти инструкций в него не включена. Звук Game Gear PSG и FPS физического плеера этой проверкой не подтверждаются.

[Журнал проверенного прогона](../validation/petris-native.json) содержит хеш конкретного SGS. [Комплект с кадрами и исходниками](../research/archives/Petris-Kingston-Native-Replay.zip) сохраняет восемь кадров в RGBA и PNG, журнал, инструмент воспроизведения, исходник лаунчера, оригинальный картридж, архив исходников автора и лицензии. Манифест внутри ZIP содержит размеры и SHA‑256 каждого файла.
