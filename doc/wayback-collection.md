# Возобновляемое сохранение GNEX Club, GVM Club и Sinjisoft

Запущено 6 ноября 2026 года. Полное сохранение содержимого **ещё не завершено**.
Достигнут конец доступного CDX-индекса GNEX Club: 1 434 различные записи,
и `sinjisoft.co.kr`: 8 143. Сбор индексов GVM Club, `sinjisoft.com` и
тематических форумов продолжается. Полученный индекс адресов не означает,
что тела всех снимков уже скачаны.

В [настройках](../tools/wayback-sites.json) перечислены официальные домены,
три конкретных сообщества Naver и четыре блога Tistory с ранее найденными упоминаниями
платформы. Общий `cafe.naver.com` целиком не собирается.
Корейские запросы исследования: `신지소프트`, `지브이엠`, `지넥스`,
`보도자료`, `기술자료`, `자료실`, `개발자`, `SDK`, `내장 게임`.
Пресс-релизы и документация включены в общие доменные очереди; живой
[раздел пресс-релизов Newswire](sinjisoft-press-preservation.md) сохранён отдельно.

## Как работает сборщик

[wayback-harvest.py](../tools/wayback-harvest.py) использует
[первичный API CDX Internet Archive](https://raw.githubusercontent.com/internetarchive/wayback/master/wayback-cdx-server/README.md).
Запрашиваются все даты, MIME и статусы, все поддомены выбранных доменов.
Нет `collapse=digest`, `collapse=urlkey`, фильтра только успешных ответов
или ограничения одной версией страницы. Пагинация идёт через `resumeKey`.
Обработаны оба формата продолжения: отдельный JSON и маркер внутри массива.

Исходные CDX-ответы сохраняются целиком, включая повторные строки.
Одинаковые записи с полностью одинаковыми полями имеют одну задачу очереди.
Страница индекса и её следующий курсор фиксируются одной транзакцией
SQLite: прерывание процесса не пропускает записи.

Каждый replay запрашивается по точному времени с `id_`. Перенаправления
сохраняются как ответы, без перехода на нынешний живой сайт. Для каждого
реального ответа хранятся URL, UTC получения, статус, заголовки, размер
и SHA-256. Имя объекта — его SHA-256; содержимое не перекодируется.
В HTTP-пути не-ASCII символы кодируются UTF-8, а буквальный адрес CDX
остаётся в исходной записи. Искажённые корейские URL из индекса не
«исправляются» молча и не объявляются отсутствующими файлами по одному 404.

В новом режиме `--repair-urls` после неуспешного буквального запроса
проверяются максимум два явно записанных варианта корейской кодировки:
исходные Latin-1/UTF-8 байты и CP949. Имя хоста и запись CDX остаются
прежними. Кандидат принимается только при точном совпадении SHA-1 тела
с исходным CDX. Ответы 401/403, ограничения частоты и ошибки сервиса не
вызывают обходов кодировки.

`--archive-redirects` разрешает максимум два перехода **внутри Wayback**
к raw replay той же страницы/файла, включая обычный алиас `www`.
Переход на живой сайт, другой ресурс или переписанный HTML не выполняется.
Исходный исторический redirect остаётся самостоятельным ответом. Для
одной задачи общий предел — шесть HTTP-запросов, включая варианты.
Нужен тот же исходный digest: соседний снимок с другими байтами отвергается.
Фактические URL, времена снимков и заголовки всех переходов сохраняются;
они не объявляются метаданными первоначально запрошенного времени.

Статус `verified` означает совпадение SHA-1 тела с CDX. Даже HTTP 200 не
считается восстановленной страницей без этой проверки. Сохранённый
исторический 302 или 404 также может иметь правильный digest; это
подтверждение соответствующего ответа, не найденный EXE/PDF.
`mismatch`, `retry`, `unverified` и `pending` остаются отдельными состояниями.
Ошибки 503, тайм-ауты и пустые повреждённые ответы не завершают индекс.
На 429/503 загрузка тел останавливается до следующего запуска.

## Запуск и продолжение

Нужен Python 3.11+, без сторонних пакетов. Каталог коллекции храните вне
исходников или в игнорируемом `research-work/`.

```sh
python tools/wayback-harvest.py research-work/wayback --index
python tools/wayback-harvest.py research-work/wayback --download
python tools/wayback-harvest.py research-work/wayback --index --download --retry
```

По умолчанию нет общего ограничения числа страниц или загрузок. Один
вызов делает одну попытку каждого выбранного элемента, пауза между запросами
не меньше 1,5 с. Если архив временно недоступен, повторите ту же команду:
готовые страницы индекса и проверенные тела не скачиваются заново.

Для короткого проверяемого прохода:

```sh
python tools/wayback-harvest.py research-work/wayback --index --scope gnexclub --max-pages 2
python tools/wayback-harvest.py research-work/wayback --download --scope gnexclub --max-downloads 50
python tools/wayback-harvest.py research-work/wayback --index --scope gvmclub --timeout 90
python tools/wayback-harvest.py research-work/wayback --download --failed-only --repair-urls --archive-redirects
```

`--scope` можно повторять; он ограничивает и индексацию, и загрузку.
SDK, SGS, архивы, документы и исходники получают приоритет перед остальными
телами, но остальные записи не удаляются. Совпадение имени или MIME не
подтверждает, что внутри находится SDK, игра или телефонный проигрыватель.
Полученные архивы требуют отдельной статической проверки.

## Замороженный комплект

Для остановки работающего сборщика создайте пустой файл `STOP` в каталоге
коллекции. Текущий ответ будет записан, затем новые запросы не начнутся.
После удаления этого файла та же команда продолжит очередь. Состояние
не стирается; поле `resolution` хранит способы и исходы запросов к каждой
задаче. Старые SQLite-очереди обновляются без изменения записей CDX.

[package-wayback.py](../tools/package-wayback.py) делает согласованную
SQLite-копию очереди даже во время продолжающегося сбора, включает только
неизменяемые объекты, на которые ссылается снимок, проверяет их SHA-256,
весь ZIP CRC и отдельный манифест SHA-256/CRC всех файлов.

```sh
python tools/package-wayback.py research-work/wayback --output ../wayback-pass.zip --report ../wayback-pass.json
```

Оба выхода должны быть новыми. В ZIP находятся `collection/queue.sqlite3`,
исходные ответы в `collection/objects/`, выгрузки `captures.jsonl`,
`responses.jsonl`, `membership.jsonl`, `summary.json`, скрипт и настройки.
После распаковки сбор продолжается той же командой с каталогом `collection`.

Это сохранение доступного публичного индекса и ответов replay, **не WARC**
и не доказательство наличия всех когда-либо существовавших файлов сайта.
Закрытые страницы, неархивированные вложения и прежние POST-загрузки
сборщик не восстанавливает. Повреждённые кандидаты сохраняются с точным
статусом, без объявления находки SDK 1.20/1.40 или телефонного GNEX-плеера.

## Опубликованный первый снимок

[GNEX-GVM-Wayback-Partial-20261106.zip](../research/archives/GNEX-GVM-Wayback-Partial-20261106.zip):
13 756 833 байта, SHA-256
`02f8e0f834d17b44359ecd2dbaa9c9250623ea4e68e147b8310a950d6d117dc2`.
[Проверка снимка и состояния очереди](../validation/wayback-collection-pass1.json).

На момент заморозки: **24 698** задач CDX, **80** тел совпали с digest,
**26** ответов имеют несовпадение, **24 592** ещё ожидают загрузки.
Среди совпадений бывают оригинальные перенаправления и ответы 404: это
не 80 документов или новых бинарников. В ZIP 106 различных исходных
ответов, включая индексы и ошибки; 116 файлов. CRC и 115 SHA-256 манифеста
проверены. Очередь остаётся возобновляемой; продолжающийся локальный сбор
может содержать более поздние результаты, чем этот неизменяемый снимок.

SDK 1.20/1.40 и самостоятельный телефонный GNEX-плеер данным снимком
не объявляются восстановленными. Нулевые результаты конкретных
префиксных запросов Naver не означают отсутствия оригиналов вне Wayback.

[Отдельное дополнение с восстановлением корейских адресов](gvm-korean-url-recovery.md)
сохраняет 28 проверенных снимков и все попытки запросов; первый ZIP
остаётся неизменённым.

второй содержит полный согласованный снимок уже полученного локального
состояния, а не только разницу с первым.

[Следующий проход технического раздела](gvm-technical-library-pass.md)
сохраняет DOC, точные имена вложений и исходный индекс с `www`-алиасами.

соседние блоги и пути общих хостов не добавляются. ALZ, HWP, CHM, DOC
и MSI получают приоритет вместе с SDK/игровыми контейнерами.
