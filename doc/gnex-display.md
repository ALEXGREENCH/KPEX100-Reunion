# Вывод кадров GNEX

В прямом режиме SGS рабочий буфер рисования и показанный экран различаются.
`Flush()` передаёт готовый кадр на экран. Последующие рисование,
`SaveLCD()` и `RestoreLCD()` меняют память подготовки кадра, сохраняя
показанное изображение до следующего вывода.

Это описано в Sinjisoft Mobile C Library Function Reference: редакция 311,
печатные страницы 171, 217–218; редакция 313, страницы 173, 223–224.
[Исходный PDF 311](http://cfile209.uf.daum.net/attach/165521104A3E87994E43CC),
[библиография и SHA-256](reference-index.md),
[данные проверки](../validation/gnex-display-presentation.json).

## Ошибка, обнаруженная на Waterski

Оригинальный обработчик Waterski рисует меню и персонажей, вызывает
`Flush` по адресу SGS `0x5066`, а затем `RestoreLCD` по `0x506a`.
Восстановление копирует 73 216 байт сохранённого фона моря в рабочий
буфер. Старое ядро игнорировало `Flush` и читало этот буфер после завершения
события. Поэтому отображался фон, хотя оригинальная отрисовка уже
создала правильный кадр.

| Операция                   | Рабочий буфер    | Показанный экран |
| -------------------------- | ---------------- | ---------------- |
| Нарисовать фон, `SaveLCD`  | Фон              | Предыдущий кадр  |
| Нарисовать персонажей      | Фон и персонажи  | Предыдущий кадр  |
| `Flush`                    | Фон и персонажи  | Фон и персонажи  |
| `RestoreLCD`               | Фон              | Фон и персонажи  |
| Событие без нового `Flush` | Может измениться | Фон и персонажи  |

Веб-ядро сохраняет RGB565 при `Flush`, затем преобразует именно показанный
кадр в RGBA. Отпускание клавиши и следующие события без вывода его
не стирают. Телефонный профиль использует эту семантику с создания машины.
В профиле K-PEX сохранён прежний предварительный просмотр до первого
явного `Flush` или `FlushPartial`: некоторые исходные SGS рисуют стартовый
экран раньше первого запроса вывода. Это ограниченное поведение совместимости.
Настольное ядро тоже сохраняет показанный кадр после первого явного вывода.
Полная эмуляция ROM использует собственный контроллер LCD; это исправление
относится к прямому запуску SGS.

## Частичный вывод

`FlushPartial(x1, y1, x2, y2)` принимает конечные координаты области.
Оригинальный ARM-адаптер переставляет обратные границы, обрезает их по
размеру дисплея и включает конечный пиксель. Вне области сохраняется
предыдущий показанный кадр. Полностью внешняя область ничего не меняет.

В Kingston 2.12 цепочка системной функции `0x60` проходит через
`0x2005dc38`, `0x20053a34`, `0x200557a0`, `0x200506e4`.
Последний обработчик вычисляет разности координат и прибавляет единицу
по `0x20050714` и `0x20050718`, передавая размер области в `0x2004c4ac`.
Так определена включительность границ.

Настольный `GetDisplayInfo` теперь возвращает выбранную геометрию,
как веб-ядро. Иначе для тестового дисплея 64×64 родной `SaveLCD`
продолжал считать размер 220×176 и копировал 77 440 байт между буферами
по 8 192 байта. Проверка восстановления теперь использует реальные
неперекрывающиеся буферы нужного размера.

## Проверки

SGS v1/v2 вызывают полный вывод через нативный адаптер `0x20053a08`
(смещение ROM `0x4412c`), обходя диспетчер системных функций v4.
Этот адаптер тоже сохраняет показанный кадр. Иначе телефонный профиль
продолжал бы показывать начальный чёрный экран старых SGS. Отдельная
регрессия запускает оригинальные Eska2 v1 и Bubble Bubble v2 и сверяет
видимые RGBA с последними RGB565, действительно переданными на вывод.
Проверка дала сбой до исправления и проходит после него.
[Регрессии старой VM](../tests/legacy.test.mjs).

[Веб-регрессии](../tests/gnex-presentation.test.mjs) исполняют собственные
минимальные SGS оригинальным ARM-интерпретатором. Они проверяют
`SaveLCD → Flush → RestoreLCD`, последующие события без вывода,
частичный вывод, включительные и обратные границы, обрезку и полностью
внешнюю область. До исправления два исходных теста воспроизводили
исчезновение показанного кадра. После исправления проходят четыре.
[Настольные проверки](../desktop/tests/test_gnex_presentation.py) покрывают
восемь случаев через оригинальный ARM.

Неизменённые Storm of Silence Demo и Waterski после исправления дошли
до игрового процесса. В двадцати независимых запусках сравнивались
одинаковые интервалы с вводом и без него. Storm перемещает персонажа
по RIGHT/6, Waterski выполняет прыжок по UP/2.
[Происхождение SIS и SGS](gnex-devices.md#symbian-s60),
[события, кадры и проверки управления](../validation/sinjisoft-s60-gameplay.json).
