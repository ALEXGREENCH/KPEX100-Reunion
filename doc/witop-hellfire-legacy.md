# WI-TOP Hellfire: запуск оригинального SGS v1

В библиотеку веб-эмулятора добавлен **Hellfire (WI-TOP, GVM v1)**.
Это уже сохранённый пример из двух комплектов WI-TOP, теперь проходящий
прежнюю ошибку START. SGS не исправлялся и не пересобирался:
24 502 байта, SHA-256
`37a3310b683e47b90e070e8772ac3ad267be172d11799f1168a2350fe448eec8`.
[Происхождение, INS и исходные архивы](gvm-community-recovery.md).

Профиль 120×100 взят из сопровождающего INS. Конкретная модель телефона
не установлена, поэтому автоматически используется универсальный GNEX-корпус.
Это поддержка веб-интерпретатора SGS v1/v2; нативный desktop-интерпретатор
SGS v4 этим изменением не получил поддержку старых форматов.

## Причина ошибки и реализация

В чистой версии `137ed6e` START завершался исключением 15 на legacy
opcode `0xBA`, по адресу SGS `0x650` (PC после чтения — `0x651`).
MASM SDK ранее позволил установить имя **LockChatMode**. Теперь проверен
и его ABI в полученном x86-эмуляторе `2x_Cr256_Magic.exe`:

| Параметр                | Значение                                                                     |
| ----------------------- | ---------------------------------------------------------------------------- |
| Размер PE               | 1 056 768 байт                                                               |
| SHA-256                 | `2bcc2554605bc277a99ff1220db1a509f875c207221647f806d0fff3efd66f88`           |
| Таблица legacy callback | VA `0x494A68`, 243 записи                                                    |
| Callback `0xBA`         | VA `0x41C280..0x41C299`, 25 байт, шесть инструкций                           |
| Эффект                  | Снять один 16-битный аргумент; сохранить младший байт; не помещать результат |

Например, `256` сохраняет `0`, `257` — `1`, `-1` — `255`.
Преобразование к логическому значению было бы ошибкой.
Нативная инициализация ставит блокировку в `1` для одиночного режима;
проверка входа в чат по клавише вызова также исключает одиночный режим.

В Kingston legacy-диспетчер ведёт эту операцию в общий обработчик ошибки.
Адаптер Reunion обслуживает только установленный `0xBA`: снимает аргумент
через проверяемый 16-битный стек и сохраняет байт состояния. Начальное
состояние одиночного хоста — `1`. Остальные неизвестные операции продолжают
давать ошибку. `0xBB SetChatMode`, экран чата и сетевой сервис не реализованы.
Байты ROM и SGS остаются исходными.

[Эталон, дизассемблирование и результаты](../validation/gvm-legacy-chat-native-reference.json)
получены [отдельным инструментом](../tools/inspect-gvm-legacy-chat.py).
Опция `--reference` исполняет только эти 25 проверенных байтов в изолированной
памяти x86 Unicorn: без загрузчика Windows, импортов, GUI и сети, с пределом
32 инструкции. Это исполнение ограниченного фрагмента исторического кода,
а не статический анализ всего результата.

Эталон охватывает 99 сочетаний аргумента, глубины стека и предыдущего
состояния, а также все 65 536 значений 16-битного аргумента. Для 99 случаев
проверены остальные байты области VM, вершина стека и возврат в sentinel.
Адреса и выводы относятся к указанному PE; его имя само по себе не доказывает
неизменённость дистрибутива производителя.

Справочник Mobile C API 311 описывает LockChatMode и начальное состояние
на стр. 46, SetChatMode — на стр. 47. Дополнительный первичный источник —
[презентация Sinjisoft 2000 года](sinjisoft-corporate-seminar-2000.md):
слайд 19 показывает вызов `LockChatMode(0)` в Hellfire. У показанного
исходника другие версия и идентификаторы; точное совпадение сборок не заявлено.

## Управление

У этой конкретной SGS обработчик использует:

| Действие       | Исходная клавиша телефона | Альтернативы по умолчанию            |
| -------------- | ------------------------- | ------------------------------------ |
| Вверх / вниз   | `1` / `7`                 | Стрелки, крестовина или ось геймпада |
| Влево / вправо | `4` / `5`                 | Стрелки, крестовина или ось геймпада |
| Огонь          | `3`                       | `Z`, первая кнопка геймпада          |

На заставке запуск допускает нажатие клавиши. Цифры клавиатуры и цифрового
блока остаются альтернативами. Экранная клавиатура отправляет исходные коды.
Пользовательские переназначения профиля и игры имеют приоритет над этим
пресетом. Ввод остальных SGS не меняется: соответствие задано по точному
идентификатору `hellfire-witop-v1`, только для телефонного профиля.

Альтернативы объединяются существующим учётом удерживаемых действий.
Рабочая VM не получает второй произвольный слой преобразования кодов.

## Проверки и пределы

- Синтетические SGS v1 и v2 проходят 198 сравнений с независимыми
  x86-векторами: один снятый аргумент, отсутствие результата, сохранение
  остальных ячеек стека и canary. Пустой стек даёт ошибку и не меняет
  состояние; соседний неподдерживаемый `0xBB` не пропускается.
- Оригинальная Hellfire проходит START, таймер 300 мс и доходит до боя.
  Пять исходных клавиш меняют кадр относительно прогона без ввода при
  одинаковом виртуальном времени; четыре направления проверены по
  переменным позиции. Просмотрены исходные кадры до и после движения.
- Два прогона по 2 000 таймерных событий после вступления — десять
  виртуальных минут каждый — используют один seed `12345`. В точном и
  ускоренном режимах совпали последовательность всех кадров, итоговые
  переменные, состояние блокировки и таймеры. Тест отдельно проверяет,
  что реально вызывались разные пути исполнения CPU.
- Пользовательские привязки проверены поверх пресета, включая сохранение
  настроек и отсутствие влияния на другие игры и профиль плеера.

Это не полное прохождение, проверка реального телефона или решение всех
случаев зависания других игр. Первоначально звуковые подтипы `0` и `1`
игнорировались. Теперь [зуммер `0` воспроизводится](gvm-buzzer-audio.md);
[MA1 `1` также воспроизводится](gvm-ma1-playback.md) с исходными тембрами.
Для этого запуска выбран MA1, фильтрующий парную альтернативу зуммера.
Арифметика FM и аналоговый тракт пока приближены.

Повтор:

```sh
node --test tests/legacy-chat.test.mjs tests/hellfire-witop.test.mjs
node tools/replay-sgs.mjs hellfire-witop-v1 validation/replay-witop-hellfire-controls.json new-replay
```

Для отдельного эталона извлеките неизменённый `2x_Cr256_Magic.exe` из
сохранённого [раннего комплекта](gnex-early-sdk-player-followup.md), установите
`capstone==5.0.9`, `unicorn==2.1.4` в отдельное Python-окружение:

```sh
python tools/inspect-gvm-legacy-chat.py 2x_Cr256_Magic.exe --reference --output native-chat.json
```

Инструмент отвергнет другой хеш PE. Без `--reference` он только читает
проверенный PE и дизассемблирует указанные диапазоны.
